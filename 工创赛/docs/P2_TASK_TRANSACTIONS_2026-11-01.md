## 实现和证据契约

`src/smart_carrier/task_transactions.py` 复用已有初赛任务与槽位类型。会话+16位序号绑定批次、顺序、唯一实例和源/目标。相同请求重发返回原状态；相同序号不同请求拒绝，本会话不回绕复用。一次仅一个事务；不同批次同色不能复用实例。库存导入不补计数。

状态为 REQUESTED → ACCEPTED → HELD → COMMITTED。ACK只表示接收。抓取必须具备同事务的执行完成、匹配颜色、真实持料和源位置已空证据；放置必须另有晚于抓取的释放、目标在位、正确目标和落稳证据。每次提交只增加一次对应计数。源物料颜色不能仅由任务期望值填入；有效车载库存颜色可复用，但失效后须重新观测。

允许链路为原料→车载→粗加工→车载→暂存，阶段不能跳过。第一批三色暂存闭环后才允许第二批原料抓取；第二批须有已确认同色底层。第二批放置后最终层数/姿态仍依赖现场证据适配器，不能仅靠布尔测试值通过。

证据使用同一单调时钟域，拒绝旧会话、错实例、未知序号、请求前、过期和未来证据。`maximum_age` 为调用方显式参数，回放使用0.5秒作为合成用例配置，**不是实机验收阈值**。不改变用户已选择的机构无限等待，不新增固件动作超时；通信失效或结果不确定时，适配器应调用 `invalidate(reason)` 并执行既有停机策略，不能继续等待旧证据或自动重试动作。

失败/掉料/复位/未受控移动使全部槽库存和手中状态失效，迟到DONE不能恢复。保留已独立确认的历史抓取计数，失败放置不增加放置计数。恢复需新会话和实物核对；本实现不支持从磁盘恢复在途运动，也不承诺断电跨进程恰好执行一次。回放日志仅为审计，不是自动续动许可。

`can_transport()`仅表示任务层持料/在途/库存必要条件，不授予底盘运动。所有输出 `motion_allowed=false`；原运动/几何/安全门禁由各拥有模块继续负责。

## 现场接入尚缺的项目

1. 扫码设备当前唯一运行目录、串口/原始帧、多帧时效和本轮任务切换事件，尚未读取。用户转述码已保存，不能因此关闭真实扫码接入。
2. STM32协议适配器须将实际会话/动作序号的ACCEPTED、DONE、ERROR分别接入；现有Watch人工模式2完成、PWM写入或驱动ACK不能直接构造库存成功。真实执行端须在收到相同序号时保证不重复物理动作，主机账本不能替代板端幂等。
3. 实际相机/夹持/落槽确认来源、同一时钟域和新鲜度实测、动态物料实例绑定仍待贯通。当前用户快照仅供看护调试，不启用RUN-01自主入口。
4. 显示适配器须消费真实计数：运行page0保留完整任务码，完成任务并回抽签同区停车后page1两行真实计数。未写屏、未验证字体/显示/回区；现场起点仍未知。
5. 结合后续2缺失的自动源抓取/动作串联，完成一次真实入槽/出槽事务、重复报文不重复动作、漏抓/滑落不记放置，再与转动原料区联合验证。当前不要求重复已验回零、旧抓放或空载往返。

当前普通主程序仍是底盘避障骨架，未将本账本接入其运行循环；没有改实际Keil工程、下载固件、连接香橙派或发送硬件指令。现场输入和反馈接入完成前，后续3保持开放。
