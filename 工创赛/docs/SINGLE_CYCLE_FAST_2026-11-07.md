## 上位脚本（scripts/integration11_v3_fast_20261107.py）
- 闭爪：PWM 斜坡 150ms + **再等 450ms** 才上升（原 157ms 就上升，舵机70°没走完、没夹紧 → 抓取位置错）。
- 下降前 **强制 4310 在 180±3°**（实测曾漂到 163.3°，偏 17° 直接抓错料）。
- 等伸缩真正就绪（state 4 + ref + hold）再下降；下降请求被 `rejected` 就重发（最多10s）。
- 下降到位容差 3→40 raw（实测正常误差 2~4 个计数）。
- 恢复：缓开夹爪 1.2s + 复位 + 原生回零；持料阶段任何失败只 STOP，绝不复位。

## 重要结论
1. **4310"掉线"是假象**：`DM_CAN2_ModuleService` 需 `g_can_guard_ready`，而 guard 要 VM 上电后 CAN1 四个节点轮询新鲜（实测 1093ms 到齐）。VM 关闭时整条链不初始化，读出来就是 `state5/result8/pmax0`。开 VM 后只读确认：`esc_id=1, pmax12.5, vmax30, tmax10, valid_mask7, SLAK=0, ESR=0`，通信正常。
2. **臂角是抓取位置错的主因**：logical 163.3° 时下降必然抓偏，必须每次下降前校准。
3. 回顶的慢来自"真回零(驱动60RPM末段)+2mm退离"，快速预升本身与下降同速（18464/45055）。
