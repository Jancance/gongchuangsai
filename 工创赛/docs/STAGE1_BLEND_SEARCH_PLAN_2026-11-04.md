# 第1段斜向起步与两侧扫码搜索：实施前方案

用户明确：起步同时前进与横移，前进150mm后平顺转为纯横移，横移上限45cm/s；到名义扫码点仍无码，立即先朝另一起点搜索15cm，再朝本轮起点到名义停车点另一侧15cm（第二程30cm）。两侧镜像，参数集中。第一段原双起点扫码已获用户功能确认，新轨迹需重新验证，不撤销旧事实。

本次把第一段选为单段。区1由(2250,150)到(1200,300)，区2由(150,150)到同一点，车头保持+Y。两条静止到静止S曲线同时起步：纵向150mm、速度上限20cm/s；横向1050mm、速度上限45cm/s。纵向先完成后横向继续，不在纵向结束处发STOP/重开会话。为保证合成四轮预算，纵横各分配一半加速度/jerk预算，不把两个单轴满限简单相加。

既有一维四轮投影的spread判断不适合斜移，将在同一时间对齐的四轮位置中分离纵横分量，再检查剩余轮间残差。复用原唯一CAN后端、命令/反馈检查、STOP应答和停稳保护，不新增CAN所有者，不恢复轮速反向故障。

跟随保护检查参考位置与实际编码器推算位置差；旧50mm为固定值，不是官方规则。新斜移采用每轴max(50mm,20mm+参考速度×100ms)，最大允许80mm；不允许删除跟随检查。末端等待由本轨迹持续时间起算，单独集中为3秒候选；STOP500ms、停稳2秒、新鲜度等独立保护不随之放宽。遇到失联/驱动异常仍立即按原保护停机。阈值只在新斜移路径使用，不泛化修改后续阶段。

扫码过程只锁存本轮合法新码，途中识别到码沿用有序停车后显示；提前停车不宣称到了名义点。没有码且名义运动完整结束后，同服务流程提交第一次搜索，不添加人为停留；仍需四轮停稳和会话释放核验，不在原方向未停时突然反转。搜索一：区1左150/区2右150；搜索二：区1右300/区2左300，终点为名义点向本轮启停区偏150。搜索途中有码即停止；最多两次、有总截止，仍无码则停车报扫码搜索耗尽，不无限往返。

搜索距离默认15cm、速度上限45cm/s、时间与斜移跟随/末端参数集中在USER/vehicle_parameters.h；修改须通过数值/静态名义扫掠检查。所有坐标仍基于名义起点与编码器，不当作真实地面定位/避碰。搜索/提前扫码后的实际落点会改变第2段起点，未接真实位姿时不得自动按原名义第2段继续。

先验证实际纯C轨迹/投影/四轮合成和真实任务状态机，再用完整CAN后端模型及MATLAB对双起点、纵向结束时横向不停、速度/加减速预算、到位/错误数据、取消/码时序、搜索15/30cm及耗尽覆盖。模型通过后构建实际/副本两目标，保留来源SHA与备份；不自动触发实车动作。新硬件路径未验收前不宣称“丝滑”或扫码必然成功。

核对R QR-01/05/06/07、DSP-01/02、RUN-01/02/04/07、FIELD-01/02/06、PWR-01、MECH-01/02；E QR-02/03、RUN-05/06、LOC-02/03/05/07、MOT-01～04。速度、阈值、搜索与斜移是E，非新增R；FIELD-05/OBS-03/QR-04等Q保持待技术答疑确认。实际地速、制动、包络、重复性、实时X/Y、视觉及新整段验收开放。
