## 3. 高度参数集中放在哪里

后续教学建议由用户在真实F407工程建立`USER/app_mechanism_config.h`，集中放机构几何参数；具体路径以用户工程结构为准。现场通常只改该文件的原料盘高度及配置版本，不到各动作函数寻找散落常数。

以下只是未来插入的写法示意，90.0不是实测默认值，当前也未创建该头文件：

```c
/* 场地原料转盘上表面离地高度，单位：毫米；90.0仅为示例，现场按实测值修改 */
#define RAW_TABLE_SURFACE_HEIGHT_MM       90.0f

/* 机构几何参数版本；高度等几何参数修改后递增，并与视觉端核对 */
#define MECHANISM_GEOMETRY_REVISION        1U
```

例如现场测得85mm，就把高度改成`85.0f`，重新编译下载，并执行下文标定与单件复核；不得仅因代码里填了值就把配置标记为已验收。几何设置在一轮任务开始前锁存，运行中不切换高度。

| 候选参数 | 基准及用途 |
|---|---|
| `RAW_TABLE_SURFACE_HEIGHT_MM` | 场地地面Z=0、向上为正，原料盘上表面实测高度；本轮准备覆盖80～100mm |
| `MATERIAL_HEIGHT_MM` | 物料本身高度，用于可见顶面、抓取及间隙计算；不从旧桌面样品直接继承 |
| `RAW_GRASP_OFFSET_FROM_SURFACE_MM` | 夹爪工具控制点抓取时相对盘面的目标高度，按夹爪/物料实测定义；不能与物料顶面高度混用 |
| `ONBOARD_CARRIER_SURFACE_HEIGHT_MM` | 车载270°三槽盘上表面离地高度，独立实测；原料盘高度变化不修改它 |
| `CLEARANCE_ABOVE_TARGET_MM` | 接近/撤离留空量；值按实际机构、物料、盘边及越障路径验证后填写 |
| `MECHANISM_GEOMETRY_REVISION` | 当前几何参数版本，双方启动核对并随记录保存 |

抓取目标关系：`工具目标离地Z = 原料盘上表面离地高度 + 已标定抓取相对高度`。P1随后按机构归零基准、工具偏置和实际机构模型转换为轴目标，再检查软行程/碰撞/可达性；不得把80～100mm直接作为电机脉冲或舵机角度。车载放料采用车载盘高度，雷达扫描高度另属雷达profile。

80～100mm是现场候选范围；建议覆盖80、90、100mm及实际使用值（E，测试点不是官方要求）。高度超出已验证范围或记录未完成时重新评估，不静默夹紧到80或100继续动作。

## 4. 高度变化怎样与视觉对应

目前P2的`calibration.py`/`calibrate_ground.py`是单个平面的二维单应性，尚无按盘高自动重算三维投影的实现。P2模型已有时间戳、来源/标定/跟踪ID及XY，但缺原料盘高度、工作平面ID、几何版本和抓取Z的完整合同；不能把计划字段说成已经贯通。

平面单应性依赖观测平面；改变盘高后，旧平面的像素到毫米映射不能自动继续有效。该判断依据[OpenCV平面单应性说明](https://docs.opencv.org/4.13.0/d9/dab/tutorial_homography.html)，不是竞赛规则。具体按当前方案处理：

1. 明确视觉看的是盘面标记、物料顶面还是其他特征；看物料顶面时，投影平面还包含物料高度。
2. 当前二维方案在对应实际平面重新标定，或选用已验证且匹配的高度profile；验证中心与边缘的独立毫米误差。不能只改机械臂Z而继续沿用不匹配的H矩阵。
3. 以后可在可靠相机内外参/机器人位姿基础上实现视线与新高度平面求交，使同一个高度设置驱动几何换算；此为候选，当前未实现，仍需独立实测。
4. 仅盘高变化不意味着相机内参本身变化；相机安装、焦距、分辨率等变化则另按CAL-03重验相关标定。
5. 高度或标定版本改变后，旧目标和跟踪/预测缓存失效，取得新观测后再进入抓取。

参数单一来源目标：用户在P1集中入口改高度，P1发布实际生效的高度/几何版本，P2选取或验证匹配平面并回报标定版本；双方一致才允许抓放。该同步载荷尚待实现。实现之前用双方记录人工逐项核对，不能宣称改一行便自动完成所有视觉标定。

## 5. 视觉组与电控的整合内容

先在搬运/底盘/路线基础阶段冻结接口语义，最终在新阶段8集中联调。P2现有颜色、反光失检、跟踪、标定门禁继续执行；以各自真实证据进入联调，不能因为日期或计划重排就跳过。

| 方向 | 候选交接内容（待实现/冻结） | 责任 |
|---|---|---|
| P1→P2 | 当前有效底盘位姿/时间戳、机械臂状态、三槽库存与有效性、原料盘高度及geometry_revision、执行序号/故障 | P1提供测量/状态，区分有效值和估计；不把命令值当反馈 |
| P2→P1 | `source_id`、`work_plane_id`、颜色/实例/track ID、目标XY及其坐标系、时间戳/有效期、误差界、calibration_id和geometry_revision | P2输出观测/目标；P1按已确认高度配置推导工具Z并决定动作，不接收裸PWM |
| 双向 | 同一坐标和毫米/角度单位、时钟关系、动作序号、`ACCEPTED/DONE/ERROR`、高度/标定版本 | 版本不匹配、过期/身份不确定、不可达或未就绪时拒绝动作；重复序号不重复执行 |
| P2验证→P1/任务层 | 抓后、放后及槽位占用的当前视觉证据 | 执行完成与视觉证据共同成立才更新库存和抓放计数 |

`ACTION_TARGET`已有预留命令字不等于高度载荷已实现；本轮不改冻结命令字、运行配置或实际Python模型。后续双方扩展解析/校验后做黄金向量、错误版本/高度/旧帧拒绝测试。

联调顺序：双方只读状态和版本核对 → 毫米目标干运行比对 → 机构已回零、几何/安全通过后的单件取料上车 → 三槽与动作组 → 实际移动原料预测抓取 → 真实障碍地图与路线融合 → 双起点完整任务及失效测试。原料运动抓取保留用户“不等停”的目标，须满足身份、新鲜度、时钟/延迟、预测误差和P1执行条件；车载槽盘分度仍须到位停稳后允许手臂进入，二者不是同一运动对象。
