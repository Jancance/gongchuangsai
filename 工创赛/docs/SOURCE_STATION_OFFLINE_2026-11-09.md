# 原料区停车纠偏→手动扫码→视觉调用pzq：离线候选

## 本轮范围与当前结果

用户要求将底盘行驶与视觉抓放分阶段，底盘到原料区后先完成真实视觉纠偏，再由用户手动扫任务码，按任务颜色视觉抓取；随后验证动态转停、装载完成/第三段、第一二段一键串联。用户确认设备未就绪，本轮只完成离线代码，不连接相机、香橙派、下载器或小车，不烧录/复位/发动作，不上传GitHub。

已验`handoff/pzq/`及其AXF保持不变。新工作工程为`tmp/source_station_offline_20261109/project/gongxun-f407.uvprojx`，在线/Offline目标仍为`Vehicle_LiftRuler`、`Vehicle_LiftRuler_Offline`；这两个旧目标名不表示候选是机械隔离测试模式。完整候选交付在`handoff/source_station_offline_20261109/`，以该包和证据manifest核对，不能用新源码解释旧pzq板端符号。

## 已实现的阶段与职责

| 状态 | 所属任务/行为 |
|---|---|
| 行驶中 | 原TaskA/底盘路线执行；原料区抓放不启动 |
| `SS_WAIT_PROFILE` | 原料区到位后等待有效现场标定、机械参考/安全位；不会默认写有效位 |
| `SS_ALIGN` | TaskA经现有`Stage2Body`提交纠偏、等待真实完成并重新取图；CAN任务仍是唯一电机总线owner |
| `SS_WAIT_QR` | 纠偏完成且停车会话保持后打开扫码器，等待用户本次新扫任务码；看护调试可等待人工，不因原阶段120秒截止误停 |
| `SS_READY` / `SS_PICKING` | CAN任务依据任务颜色与新鲜真实视觉目标选左/右/下区域，复用pzq运动组 |
| `SS_DONE` | 三件机械结束且真实抓放证据已提交账本；本阶段停留，不自动进入第三段 |
| `SS_FAULT` | 保存原因；底盘/机构各原owner继续服务取消与STOP，不清故障伪装成功 |

阶段分离不是新增并行电机线程。仍由原`App_CanTask`独占CAN1/CAN2收发，TaskA只发布路线/扫码和停车上下文。等待扫码或抓放时，底盘新启动准入显式报告station占用；如果底盘会话发生改变或开始移动，视觉抓取许可失效并请求停止。VM保持只对原料区已有holding范围生效，普通底盘结束逻辑不变。

临时看护流程按用户要求：第一段不等待任务码、不造码；到原料区纠偏后才打开真实扫码。这个开关为`SOURCE_STATION_MANUAL_QR_AFTER_ALIGNMENT`，它是E调试流程，不作为RUN-01正式比赛验收；正式一键全场的扫码/任务时机要后续再恢复和联调。

- 候选`startup_axes.c`/CAN适配：把旧“仅伸缩回零PC13调试开关”与可复用回零后端拆开。恢复到位使命时仍保留真实伸缩参考/保持后端，不造原点；pzq原文件未改。
- `vision_app/code/source_alignment_session.py`：既有A边界/标定预览/MA1编码之间的无设备会话适配，消费MR1请求并为当前帧生成MA1。它不打开相机/串口，不替换识别算法，不从像素直接猜毫米。主应用仍需把真实帧边界、采集时刻和唯一串口送入此适配器。

## 真实观测与配置接续

### 纠偏

候选的`stage2_site_profile.h`当前仍是未配置0值，不会发运动。旧`calibration/source_paper_finalstop_20261106.json`保留有意义的纸面H和候选车体变换，但其中`plane_to_chassis_verified=false`、`pose_binding_verified=false`、`motion_allowed=false`，不得直接翻成true。设备就绪后复查当前相机/分辨率1920×1080/安装/臂姿和实际有效配置，利用已有测量补足车体轴向、毫米符号、盘心目标与实际纠偏验证；不要求无原因重做所有方纸或HSV。

相机侧应由现有单一采集/串口owner调用`SourceAlignmentSession.receive()`和`observe()`。输入是检测到的真实边界点和经验证的曝光时间/年龄上界；`read()`完成时刻不能冒充曝光时间。MR1/MA1绑定run、request、camera/calibration/mount/height/target等版本，CRC/过期/半帧/重发不延长旧请求截止。圆心只提供平移，yaw=0仅在实际航向保持已验的前提下作为平移纠偏声明，不伪造圆盘测航向。

当前底盘微调使用原离散位置接口，最小10mm、单轴上限20mm、最多3次，先修最大分量，每步后新图重验。闭环持续收敛、车道/扫掠、2～10mm残差如何满足实际夹爪捕获范围，仍须实车决定；本轮没有提高微调精度或默认扩大容差。

### 手动扫码与视觉取料

纠偏后扫码器仅接受本窗口中新收到的合法四段码，按实际批次1的前三色选择物料。`Vision_SetTask`/实际解析器保留四段校验，颜色号不等于区域号或载盘槽号。源码中的姿态lookup沿用已验pzq三个区域，但必须验证当前相机区域到这三条路径的绑定。

旧`CC 02 left right down DD`只包含区域颜色，没有曝光年龄、唯一物料实例、实际停盘/剩余抓离时间。候选不会从颜色或串口到达时间虚构这些信息。实际跟踪/时钟桥应从原CANowner调用`SourceStation_OfferTarget()`，提交run、pose_version、对应material_cycle、实例ID、经对时的采集时刻、usable_until、停稳/扫掠与抓离预算。现在没有默认真实提供者。

每件抓牢/放稳由已有`Vision_ReportGrasp`/`Vision_ReportPlaced`真实提供者提交，且绑定当前run/sequence/slot、实际观察时刻。机械软件完成和PWM不会自动增长真实库存；缺放稳证据时等待，不擅自抓下一件。下一步现场可用实际相机/传感观察绑定提供者，不以Watch写成功标志代替。

### 机械参考和行驶准备

本候选没有在未知升降位置自动回零。需要真实顶部/伸缩参考、4310新反馈和当前安全位都有效，才允许进入纠偏/抓放。`SourceStation_MechanicsReady()`只读这些状态，不生成参考。行驶阶段的原平台/启动和原料区机械准备仍需与队友实车核对；恢复mission时不把独立伸缩回零当升降也已建参考。缺机械参考时reason8等待，后续由已知条件下的真实准备完成。

## 下一步顺序

1. 设备就绪先核有效视觉配置、新数据与已有标定，补齐现场profile和当前机械准备；低幅实际底盘纠偏后用新图确认。识别异常先调阈值、保存并采新数据，不先改算法。
2. 对准后通知用户扫本轮任务码，绑定实际视觉元数据/抓放提供者，按任务颜色调用pzq；验一次完整三件，保留不同任务/区域排列和失败证据。
3. 再验转盘转动→停止、正反转/实际速度/停盘角度与抓离预算；固定姿态三件成功不扩展为任意停盘相位通过。
4. 真实装载完成后接第三段route-and-stow分支，再做起停区第一、第二段一键连续验收。当前station不自动进入第三段，既有route3验证位保持独立。

## 伸缩速度答复

当前pzq伸缩指令106RPM、加/减速600RPM/s，未因这轮工作改变。当前X固件梯形位置指令手册范围最高3000RPM，驱动`Vm_Limit`还会进一步限速；本轮没有读取实时Vm_Limit，3000不是本机载荷/行程已验最高速度。手册Emm固件空载6000RPM+属于另一模式，不可套入当前指令链。现有SPF组还显式固定106RPM，提升速度需要独立修改/验证，不能仅改Watch数值。
