# 灰色车道巡线、路口、随机避障与回启停区逻辑

## 1. 本专项涉及的规则基线

### 规则事实（R）

- `FIELD-01`：场地2400×2400mm，启停区1/2均为300×300mm。
- `FIELD-02`：起点由抽签决定，结束后返回同一个启停区。
- `FIELD-06`：离开启停区后，车体主体铅垂投影必须保持在灰色车道内。
- `OBS-01`：黑色随机障碍为 `φ50×100mm`，位于灰色车道。
- `OBS-04`：中央十字车道宽400mm。
- `RUN-01`：完全自主、一键启动，不得遥控或运行中触碰。
- `RUN-04`：必须防止15秒停滞；等待转盘时规则增加8秒。
- `MECH-01`：初始整机投影和高度必须符合300×300×400mm限制。

### 工程建议（E）

- `FIELD-03`：用 `start_id=1/2` 配置两套初始位姿和二维码路径，主体状态机共用。
- `FIELD-04`：按整车投影完全进入300×300mm启停区并停止的保守标准设计回区确认。
- `FIELD-08`：固定拓扑地图与车道/路口/功能区在线定位结合，功能区再做局部精定位。
- `OBS-02`：结合区域、尺寸、任务状态区分黑色障碍和黑色任务物料。
- `OBS-05`～`OBS-08`：按整车动态包络规划，无安全通道时全局换路或停车，并覆盖指定困难场景。
- `RUN-05`～`RUN-06`：每个导航状态必须有超时、有限重试、降级路线和安全出口。

### 待技术答疑（Q）

- `FIELD-05`：回启停区最终判定标准——**待技术答疑确认**。
- `OBS-03`：障碍数量、禁区、最小间距/通行宽度、碰撞/推动判罚、每轮是否重摆——**待技术答疑确认**。

本文件中的视觉方法、阈值建议、状态划分和测试次数是工程设计，不是官方规则。

## 2. 现有功能审计

| 功能 | 当前状态 | 现有证据 | 主要缺口 |
|---|---|---|---|
| 灰色车道巡线 | **缺失** | `Observations` 有 `lane_left_mm/lane_right_mm` 字段 | 两侧边界目前只是默认 `-200/+200mm`，没有从图像检测灰色车道、中心线、航向或置信度 |
| 十字路口判断 | **缺失** | 无路口数据模型、检测器或测试 | 不能识别直行/左/右分支，不能把视觉路口与地图节点关联 |
| 黑色随机障碍检测 | **部分具备** | `DarkObstacleDetector` 使用LAB亮度、形态学、连通域和单应性投影 | 尚未限制到灰色车道语义区域；未可靠区分黑色任务物料、阴影、线缆和路沿 |
| 障碍时间稳定 | **基础具备** | `TemporalObstacleFilter` 要求连续稳定帧 | 只有按排序位置比较，缺少目标ID、遮挡处理、进入/退出迟滞和速度估计 |
| 局部避障 | **基础具备** | `LocalAvoidancePlanner` 膨胀障碍并搜索横向走廊 | 只生成三段简化航点；未考虑车辆长度、曲率、动态转弯包络和路径跟踪误差 |
| 近距冗余停车 | **首版缺失** | 规划器保留ToF 180/350mm条件接口及STM32心跳检查 | 首版三路ToF为`NOT_PRESENT`，不得把缺失值当作安全；是否启用由实车盲区测试决定 |
| 全局绕行 | **缺失** | 只有 `GLOBAL_REPLAN` 枚举返回值 | 无赛道拓扑图、代价、封路边、重新选路及执行闭环 |
| 双起点 | **缺失** | 无 `start_id` 配置和状态 | 不能按抽签选择起点1/2、初始位姿和二维码路线 |
| 回同一启停区 | **缺失** | 无返程目标或进入区状态 | 不能规划返程、识别目标启停区、判断整车投影完全进入并停止 |
| 导航超时恢复 | **缺失** | 只有高层 `RUNNING/SAFE_STOP` | 无任务级导航子状态、单状态deadline、有限重试和15秒预算管理 |
| 实际运动闭环 | **缺失** | `main.py` 当前只打印规划结果 | 尚未将安全路径目标通过UART交给STM32，也未消费PAW3395/HWT101状态完成闭环；ToF首版不接入 |

结论：现有骨架适合离线验证障碍分割和局部几何，但不能据此宣称已具备巡线、过路口、完整绕障或回区能力。

## 3. 完整导航分层

```text
前视相机
  └─ 图像质量/时间戳检查
      └─ 地面矫正（鸟瞰/毫米坐标）
          ├─ 灰色车道与边界 → LaneObservation
          ├─ 十字/岔路分支 → IntersectionObservation
          └─ 黑色障碍候选 → ObstacleObservation

STM32 → PAW3395位移 + HWT101航向 + 电机速度闭环/心跳 + ToF状态`NOT_PRESENT` → RobotState

Lane/Intersection/Obstacle + RobotState
  └─ 定位与拓扑节点匹配
      └─ GlobalRoutePlanner（起点/任务区/返程）
          └─ LocalTrajectoryPlanner（巡线/转弯/绕障）
              └─ SafetySupervisor（车道包络/新鲜度/通信/超时；ToF后续可插拔）
                  └─ UART目标 → STM32速度与位姿闭环
```

必须保持接口分层：视觉输出观测和置信度，规划器输出安全轨迹，Orange Pi不直接输出裸PWM。

### 3.1 场地位姿来源

- P1以PAW3395二维地面位移和HWT101航向生成短时 `x/y/yaw`；项目不使用ICM42688。
- 电机编码器仅负责轮速闭环和打滑/堵转诊断，不作为场地X/Y位置主源。
- PAW3395/HWT101均为相对传感器，必须由 `start_id=1/2` 初始位姿启动，并在路口、功能区和启停区接受P2视觉纠偏。
- `Lift_Stat`、低SQUAL、异常Shutter、数据过期、HWT101超时、定位跳变或标定ID不匹配时，位姿标记无效；规划器必须减速、停车或进入 `RELOCALIZE`，不能继续盲积分。
- 机械、接口、标定和替代OPS-9门禁统一引用 [PAW3395＋HWT101底盘定位专项计划](LOCALIZATION_PAW3395_HWT101_PLAN.md)。

## 4. 灰色车道巡线逻辑

### 4.1 视觉处理

1. 检查帧时间戳、标定ID、曝光状态、清晰度和遮挡比例。
2. 对前视图像去畸变，再用地面单应性生成固定毫米尺度鸟瞰ROI。
3. 在LAB/HSV中建立灰色车道候选；结合低饱和度、亮度范围和场地背景校准，不使用单一固定RGB阈值。
4. 用连通域、边界连续性和已知车道宽度约束去除阴影、物料与外部区域。
5. 分别拟合左右边界或直接拟合可通行区域中心线，输出多个前视距离处的中心点。
6. 计算横向误差、航向误差、有效车道宽度、可见距离、置信度和拒绝原因。

建议观测合同：

```text
LaneObservation
  timestamp_ns, frame_id, calibration_id
  left_boundary_mm[], right_boundary_mm[], centerline_mm[]
  lateral_error_mm, heading_error_rad
  visible_range_mm, confidence, rejection_reason
```

### 4.2 控制与失效

- Orange Pi输出受限的线速度/角速度或短时位姿目标，STM32完成编码器闭环。
- 远处预瞄用于平滑航向，近处预瞄用于保持车体包络不越界；速度随曲率和置信度降低。
- 必须按包含软线、屏幕和传感器的完整车体包络检查边界，不能只看中心线。
- 单帧视觉丢失不得立即急转；仅当PAW3395/HWT101位姿仍新鲜有效时，才可在严格短时预算内减速保持；定位质量同时失效则停车。
- 连续丢失、观测过期、宽度不合理、左右边界互换或包络将越界时进入 `SAFE_STOP/RELOCALIZE`。
- 具体阈值、预瞄距离和控制增益必须由实车标定，不在当前阶段写死。

## 5. 十字路口判断逻辑

### 5.1 识别方法

1. 在鸟瞰可通行掩膜中设置近、中、远三个检测带。
2. 统计前、左、右方向的连通通道宽度和延伸长度，生成分支候选。
3. 使用骨架/中心线、轮廓或霍夫线作为辅助证据；不能只靠某一行像素突然变宽。
4. 连续多帧满足几何条件后才发出路口事件，并用进入/离开迟滞避免同一路口重复计数。
5. 将视觉路口与“里程计预计到达的下一个拓扑节点”联合匹配。若视觉分支和地图预期冲突，先减速重定位，不能盲转。

建议观测合同：

```text
IntersectionObservation
  branch_left, branch_straight, branch_right
  stop_line_or_center_y_mm
  intersection_type, confidence
  event_id, timestamp_ns, rejection_reason
```

### 5.2 通过路口

1. `APPROACH_INTERSECTION`：减速、确认事件稳定、读取全局路线的目标出口。
2. `ENTER_INTERSECTION`：锁定本次出口，禁止因短时分割波动来回改变选择。
3. `TURN_EXECUTE`：HWT101航向闭环配合电机轮速闭环执行有界转弯，同时持续检查PAW位移、障碍和车体包络。
4. `REACQUIRE_LANE`：重新捕获目标车道两侧边界，连续稳定后恢复巡线速度。
5. 超时或捕获错误：停车，限次重定位；仍失败则选择安全降级/结束，不能无限等待。

## 6. 随机障碍检测与避让

### 6.1 感知融合

- 先得到灰色车道掩膜，再只在可通行车道内寻找黑色障碍候选。
- 用底边毫米位置、投影尺寸、纵横比、接地关系和多帧稳定性验证 `φ50×100mm` 候选。
- 黑色任务物料结合功能区语义和任务状态排除；阴影结合亮度梯度、纹理和时序排除。
- 首版不接入三路低位ToF，P1固定上报`NOT_PRESENT`，P2不得将缺失距离、零值或历史值当作前方无障碍；首版避障验收依赖前视视觉、车道包络、保守速度和通信失联停车。
- 后续若实车近距盲区不能通过零碰撞/零越界门禁，再启用预留ToF；弱回波、超量程或过期数据标记为未知，视觉与ToF不一致时采用更保守结果。

### 6.2 规划顺序

1. 按“障碍半径 + 车体动态半宽 + 定位误差 + 安全余量”膨胀障碍。
2. 在灰色车道可用包络内生成左绕、右绕和停车候选。
3. 对候选检查边界、最小间距、曲率、制动距离、回归原车道能力和新鲜观测。
4. 有安全局部轨迹：减速执行，经过障碍后重新捕获车道中心。
5. 无安全局部轨迹：返回 `GLOBAL_REPLAN`，在拓扑图中临时封锁该路段并选择另一条路线。
6. 无全局替代路线或感知不确定：安全停车并在15秒窗口前完成有限重试或主动结束。

当前 `LocalAvoidancePlanner` 仅覆盖第1～4步的简化骨架；第5步目前只有返回值，没有实际实现。

## 7. 全局路线与双起点

建立配置化拓扑图，不把路口顺序散落在视觉代码中：

```text
Node: START_1, START_2, QR, JUNCTION_*, RAW, ROUGH, TEMP, STACK
Edge: 起点、终点、长度、允许方向、车道宽、预期路口出口、是否被障碍封锁
RouteContext: start_id, current_node, target_node, planned_edges, blocked_edges
```

- 一键启动前读取并锁存本轮 `start_id`，同时保存 `home_node=START_1/START_2`。
- 起点只改变初始位姿、第一段路线和最后返程目标，不复制整套任务状态机。
- 每到路口用视觉事件和里程计共同推进 `current_node`；不能按固定时间假定已经过路口。
- 遇到不可通行路段时临时提高该边代价或封锁，在同一拓扑图上重新规划。
- 所有固定地图坐标都是先验，车道/路口在线观测用于修正漂移。

## 8. 回同一启停区逻辑

1. 完成最后任务后进入 `PLAN_RETURN_HOME`，目标固定为启动时保存的 `home_node`。
2. 使用当前拓扑节点重新规划返程，不能简单倒放一串定时动作。
3. 返程仍执行巡线、路口确认、随机障碍检测和必要的全局换路。
4. 到达启停区入口后进入低速 `APPROACH_HOME`，通过启停区边界/角点或专用地面特征做局部定位。
5. 规划车体中心目标时纳入整车半长、半宽、朝向、定位误差和制动余量。
6. `VERIFY_HOME_INSIDE` 必须确认整车四角投影均位于300×300mm区域内，且STM32报告速度为零。
7. 连续若干新鲜观测满足条件后才进入 `DONE`；失败时只允许有限次数低速微调，禁止越界或长期静止。

官方最终回区判定仍为 `FIELD-05（Q）`。在正式答疑前，第6步按最严格工程标准实施。

## 9. 导航任务状态机

```text
SELECT_START
  → LOCALIZE_START
  → LEAVE_START
  → FOLLOW_LANE
      ├─ APPROACH_INTERSECTION → ENTER/TURN → REACQUIRE_LANE
      ├─ AVOID_OBSTACLE → REJOIN_LANE
      ├─ GLOBAL_REPLAN → FOLLOW_LANE
      └─ APPROACH_FUNCTION_ZONE → LOCAL_ALIGN → EXECUTE_TASK
  → PLAN_RETURN_HOME
  → FOLLOW_LANE / INTERSECTION / AVOID_OBSTACLE
  → APPROACH_HOME
  → VERIFY_HOME_INSIDE
  → DONE

任一状态：观测过期/置信度不足/通信超时/包络不安全
  → SAFE_STOP → 有限RELOCALIZE/REPLAN → 恢复或FAULT/DONE
```

每个状态必须定义：进入条件、输出命令、成功条件、失败条件、deadline、最大重试数、安全停车动作和日志字段。建议在3秒内作出重定位/换路决策，为15秒规则窗口保留执行余量；3秒是工程目标，不是官方规则。

## 10. 后续实现顺序（P0门禁）

| 阶段 | 必须新增 | 完成门禁 |
|---|---|---|
| N0 数据与标定 | 灰色车道、路口、启停区、障碍/黑色物料数据；相机内参和地面单应性 | 数据按场景拆分，标定独立点误差有记录 |
| N1 车道观测 | `LaneObservation`、灰色车道分割、边界/中心线、置信度和诊断图 | 录制视频中不越界预测；丢帧/遮挡能拒绝 |
| N2 巡线闭环 | 横向/航向控制接口、PAW3395/HWT101健康与位姿接入、电机速度闭环、速度随置信度限制 | 直道、弯道、光照变化连续巡线；光流或航向失效时安全停车有效 |
| N3 路口 | `IntersectionObservation`、事件迟滞、路口子状态 | 左/直/右分支和离开事件不重计，错误时不盲转 |
| N4 全局路线 | 拓扑图、`start_id`、节点匹配、封路和重规划 | 两个起点均按指定路线到二维码及任务区 |
| N5 随机避障 | 车道内障碍语义、首版纯视觉保守规划、可选ToF融合、曲率可行轨迹、重入车道 | 指定困难场景零碰撞、零越界；无路时能换路/停 |
| N6 返程 | `home_node`、返程规划、启停区局部定位和四角判定 | start_id 1/2分别完整回原区并停止 |
| N7 故障与耐久 | 状态deadline、有限重试、故障注入、连续运行 | 15秒前恢复/降级；完整流程连续回归通过 |

依赖关系为 `N0 → N1 → N2 → N3/N4 → N5 → N6 → N7`。不得在N1尚不稳定时直接靠增加电机速度调试完整路线。

## 11. 必须补充的自动化与实车测试

### 离线单元/回归

- 灰色直道、弯道、宽度变化、阴影、过曝、欠曝、边界缺失和遮挡。
- T/十字路口的左/直/右组合、非路口突然变宽、同一路口不重复触发。
- 障碍中心/边缘/路口/入口/多障碍狭窄通道、黑色物料共存和假阴影。
- 拓扑图从START_1/START_2到各功能区再回原区；封锁任一可替代边后的重规划。
- 过期帧、标定ID错误、定位跳变和STM32心跳超时全部失败关闭；后续装配ToF后再覆盖弱信号/超量程/过期故障。
- 车体旋转状态下四角完全进入启停区的几何判定。

### 实车门禁

- 两个启停区分别至少完成直线离区、巡线、路口左/直/右、回原区。
- 随机障碍按基线列出的所有位置和光照组合测试，目标零碰撞、零越界。
- 路口前临时放障碍时能够停车、换路或安全结束，不能卡住超过规则窗口。
- 轮胎打滑、PAW离地/低纹理/异常增量、HWT101漂移或超时及相机短时丢帧均进行故障注入；单路ToF失效测试延后到实物装配后。
- 回区以整车四角在区内且速度为零为通过证据，保存俯视视频和状态日志。

## 12. 当前不能写死的参数
