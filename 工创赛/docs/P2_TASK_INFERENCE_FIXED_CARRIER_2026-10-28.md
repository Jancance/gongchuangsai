# 扫码颜色清单、余项推断与固定车载取料位

来源：2026-10-28用户明确要求，并确认可主动转动的是车载三槽盘；任务颜色按本地任务原文核对。R规则及此前基线冲突修订见[原文复核](RULE_SOURCE_CORRECTION_2026-10-28.md)。

## 扫码之后知道什么

初赛编码1红、2黄、3蓝、4绿、5黑、6浅蓝。示例`156+123+516+231`解析为：

| 批次 | 抓取/搬运顺序 | 粗加工目标 | 暂存目标 |
|---|---|---|---|
| 第一批 | 红、黑、浅蓝 | 1、2、3号位置 | 1、2、3号位置 |
| 第二批 | 黑、红、浅蓝 | 2、3、1号位置 | 第一批同色物料上方，即2、1、3号位置 |

初赛任务格式与颜色已明确；决赛仍按现场公布另配profile。颜色编号、批次内第几个、车载槽位号、场地位置号必须独立存储。例如“取2号颜色”表示黄色，黄色存于第3槽时转第3槽，不转第2槽。

## 颜色没识别出来时的处理（E）

满足“同轮同批的三个实体已经对应、三件确实存在、两个不同颜色已稳定确认、第三件有唯一对应关系”时，可用本批任务颜色清单扣除已确认颜色，得到第三件的颜色，并标记`TASK_REMAINDER_INFERRED`。例如任务红/黑/浅蓝，A确认红、B确认黑，则唯一剩余的C可推断浅蓝，**颜色一项为UNKNOWN不会单独阻止继续调度**。

原料盘初赛有每色两个，可能同时看到6件；只有两种颜色的识别结果时，不能把其余所有实例都标成第三色。需先通过实例/空间分组、持续跟踪和已抓取数量建立唯一对应；有多个未知、重复识别同一物料、颜色与任务冲突、掉料或过期观测时进入有界复核，不用错误推断填满任务清单。

颜色推断与位置分开：第三件轮廓/位置已确认但颜色缺失，可以使用其实际位置；第三件根本未检测到时不生成虚构坐标。车载盘的情况更直接：放入时已经确认`material_id—color_code—slot_id`并提交库存，之后可用有效库存抓取，即使当前视角看不清颜色也不强制重新识色。失控转动、掉料、断电/复位或实例冲突要使库存/盘位失效，复核后恢复。

## 固定取料位与提前分度（E）

用户指定一个固定取料工位，机械臂以后从这里取车载盘上的物料。三个槽位各有“把该槽送到该工位”的实测目标角度；固定工位位姿、三角度、零点/端点和实际到位方式还需实测，不预填15/135/255等旧示例。

执行顺序：

1. 按任务选下一件颜色，从库存查出其槽号与实例ID。
2. 确认底盘停稳，机械臂及其所持物料在盘扫掠区外，将目标槽提前分度到固定工位。
3. 到位且静止确认后，机械臂沿固定动作组抓取。有效库存可作为颜色依据，不必重复识色。
4. 确认物料已抓起且原槽已空，提交该槽EMPTY；仅发出夹爪命令或收到ACK不扣库存。
5. 手臂带料抬起并离开扫掠区后，可在手臂去目标放置期间预定位下一槽。此并行区间仍要求底盘停稳且避让空间已验；若未验，则先串行。
6. 当前物料放置完成、夹爪空闲后，再从已经到位的工位抓下一件。固定延时不能代替盘到位，抓起但未离开盘时不能抢转。

装盘反向流程：选择已确认空槽→分度到固定工位→放入→确认释放和占用→提交颜色/实例库存→撤离后再转下一槽。两批、每次从粗加工回装盘时都保持本轮/批次/搬运阶段版本，不能套用前一轮库存。

本车是有限270°分度盘，三个槽的运动路径受端点/线束约束，不能按360°循环跨端点。STM32负责执行/到位/互锁，香橙派只提供结构化槽位及任务请求，不发裸PWM。

## 本轮已实现与未实现

新增`src/smart_carrier/task_materials.py`和独立初赛配置`config/task_materials_preliminary_2027.json`，纯逻辑实现：扫码任务转两批颜色/位置、第二批同色码垛位置推导、唯一第三件颜色推断、按有效库存查目标槽、固定工位取料决策、持料离盘后的预分度与夹爪忙时拒绝下一抓、抓起/空槽双确认后库存提交。

`tests/test_task_materials.py`加既有任务码测试共20项通过；涵盖颜色号不等于槽号、两色推断、位置不伪造、6件/重复ID/冲突色/旧批次/过期拒绝、完整颜色结果、不能用ACK扣库存、取料重复提交拒绝、手臂未撤离不能转盘。证据`evidence/p2-task-carrier/2026-10-28/review.json`。复现命令：

```powershell
$env:PYTHONPATH='src'
python -X utf8 -m unittest discover -s tests -p 'test_task*.py' -v
```

这些是离线纯逻辑与合成输入测试；**尚未接入板端普通主程序、STM32执行器或真实扫码/库存反馈**。旧`parse_task_code`兼容入口及未选profile的默认执行锁保持；新增初赛接口显式加载新配置，不把原默认未知状态静默升级为可运动。实际适配还需带序号的事务、反馈新鲜度、超时/有限重试、占用/夹持证据、故障使库存失效及板端部署。所有本轮决策输出`motion_allowed=false`。
