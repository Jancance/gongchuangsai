# 伸缩回零后偶发撤VM：实施前方案

用户要求彻底排查，并按同一最终版本整组验证。实机EX1：reason5、command0x3a、exchange1、flags0x02、service_gap1ms、phase8。说明状态应答成功，到位bit1=1、使能bit0=0、堵转/保护bit2/3=0；不是这次查询超时或服务超限。VM任务cause4/联合cause11，随后取消底盘。不能由flags0x02推断电池或EN引脚一定正常。

本地厂家V1.0.5_260527手册第50页规定F3 AB 01 00为使能，73～74页给出3A位定义；16页En=L/H/Hold说明外部使能脚可能影响使能。手册没有证明本机这次为何失能，不将“回零自动失能”写成已确认厂家行为。

源码确有缺口：回零完成→零速→读取位置后直接reported=1/state4，后续保持监视发现未使能便撤VM。新增完成交接阶段，只有此阶段允许一次显式使能并核回读；尚未完成时不放行底盘：

1. 保留原回零状态、超时、零速、位置读取；保存本次结束位置。
2. 读驱动状态，故障/堵转仍立即失败；再次核零速。
3. 下发STOP结束旧动作，再发送一次使能，要求有效ACK，不改驱动菜单，不发位置/速度目标或设零。
4. 连续三组新鲜的“已使能/无保护→零速→与完成位置相差≤2°”回读后才发布准备完成。
5. 独立交接2秒截止；持续不使能、ACK/查询失败、位置漂移、服务超限或取消都失败，不无限重试。交接阶段不被旧“准备2500ms”误计，也不延长原回零11秒截止；原联合15秒总截止保留。
6. 已发布保持后再次掉使能仍故障停车，不在运行中自动重新使能。记录是否已完成三组确认、使能发送次数、状态与位置偏差，便于区分交接缺口和后续硬件/外部命令失能。

整组验证要包含旧错误复现、回零结束暂时失能可建立保持、持续失能、保持后掉使能、堵转保护、使能ACK失败、位置跳变、服务超限，以及原双起点斜移/搜索/有码/无码/取消/通信故障/同次上电新轮。DM、外设与轮响应仍是模型，不把其通过当物理根因全部排除。

R核RUN-01/02/04、PWR-01、MECH-01/02、FIELD-02/06、QR-01、DSP-01；E RUN-06、LOC-03/05/07、MOT-02/04。交接/确认参数是E，R不变，FIELD-05/OBS-03/QR-04等Q待答疑。实物连续复测、EN输入/地址/供电原因和新版稳定性仍须最终现场核验，不能提前承诺物理上绝不复发。
