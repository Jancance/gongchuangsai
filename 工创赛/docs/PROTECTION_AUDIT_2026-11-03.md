## 5. “反向”还剩哪些判断

1. **轮速反馈反向故障detail10/11：已经删除。**
2. **旋转指令禁止换向：仍存在。** `heading_session.c:211`的HS_CAUSE_REVERSE=7，以及`chassis_auto_test.c:1516`的同一旋转会话指令符号限制。它们看的是要发出的旋转指令，不是轮速反馈；当前第1段没有底盘旋转动作，不是此前横移受阻的路径。若希望超调后自动反向纠正，需要先设计零速换向/制动过渡，再同时替换两处逻辑。不能仅删一处认为已实现反向纠偏。
3. **位置倒退/异常位移检查：仍存在。** 编码器均值倒退超过5mm等走distance故障5，是真实位置一致性判断，可能间接拦下实际反向位移；不属于已删的轮速反向误报。

## 7. 故障码如何读

不同变量的相同数字含义不同。例如vehicle cause8=底盘失败、backend cause8=速度/命令异常、DM result8=位置包络异常；不能只说“故障8”。

### 任务层 g_vehicle_cause

| 值 | 当前含义 |
|---|---|
| 1 | 未就绪/当前准入失败；不等价于电机坏 |
| 2 | 人工取消 |
| 3 | 启动机构Begin失败 |
| 4 | 平台或启动机构故障 |
| 5 | 段截止/启用时的演练截止 |
| 7 | 路线装载、准入、完成状态重置或重入失败 |
| 8 | 底盘流程失败，继续看backend cause/detail |
| 9 | 屏幕发送失败，不是实屏应答 |
| 10 | 仅连续模式：提前扫码后需实际位姿重规划 |
| 11 | 动作行/物料索引异常 |
| 12 | 机构动作失败，继续看arm/DM/回零原因 |
| 13 | 机构拒绝接单 |
| 15 | 工位目标/参考/动作参数未准备好 |

## 8. 结论与建议顺序

先做“故障可解释”：按键准入失败输出具体原因，记录扫码拒绝理由，保留完整首故障链。然后清理不用的旧调试入口、重复检查和过大的日志缓存；再处理屏显失败的分级与有限重试，以及可测量的超时/位置阈值。最后在确有需求时实现旋转反向纠偏和统一恢复流程。不要先删硬件反馈、停止确认和坐标有效性来让动作勉强启动。
