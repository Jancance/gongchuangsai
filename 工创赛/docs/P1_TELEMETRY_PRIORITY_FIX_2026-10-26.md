# 停车后状态遥测发送修复（2026-10-26）

## 触发与原因边界

A2实测前进约210cm、右偏约4cm。最后TM tick62300已有四轮0、VM关和后端DONE，但还没有完整phase/sequence完成；之后CT2、BT1、PM1持续抵达，主机0.6秒无新TM，按原保护发送STOP。只读补采确认完成1/1和无板上故障。保留原run-once结果telemetry_timeout，不改写为software_complete。

旧TM在发送尝试前推进100ms时钟，即使串口忙而失败也延后重试。诊断与TM共用忙拒绝单缓冲，停车持续导出可与TM尝试形成固定错开。注入45ms诊断占用已复现漏发机制；未测真实串口忙区间，不把模拟时长说成实测。

## 修复

1. TaskA先尝试TM，再处理PE2/HF2/CT/BT1/PM1。
2. TM成功排队才推进100ms周期，忙时下轮重试；首次状态无需先等100ms。
3. 五类诊断仅在已有TM排队成功、下一次TM未到期的窗口尝试，保留原40/60/70ms最早间隔及VM条件。

没有阻塞等待或无界发送队列。帧结构、历史游标成功才前进、主机0.6秒超时、保活/STOP和所有运动保护不变。串口仍可能忙或丢帧；重点是不让诊断在TM到期时继续抢占。seq仍按原逻辑每次格式化尝试递增，缺口不代表同数量电机命令丢失；诊断导出可能延后。
