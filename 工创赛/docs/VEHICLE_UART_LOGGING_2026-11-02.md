# 整车单阶段USART1日志与仿真数据约定

日期：2026-11-02。用户要求：USART1无线日志用于八段调试、提速、底盘融合动作算法及后续仿真；参数在中文源码入口修改，不通过Watch或串口写参数。

## 当前已实现与待接入

- 电脑端 `scripts/vehicle_uart_capture.py`：只读串口，保存完整原始字节、逐帧JSONL、按协议/字段版本分表的CSV和质量统计。可以离线重放旧日志，不发送启动、KEEP、调参或停止命令。
- 现有TM1、PM1、PE2/PE3、OD1、OP1、HF1/HF2和批次/时序帧沿用现有解析器。未知协议保留原始内容；只做CRC核验时不猜测字段单位。
- 固件新增WF1及只读 `ChassisAuto_ReadWheelLog`。观测各轮已应答目标、实测轮速、主控记录的应答时刻、反馈接收时刻、反馈年龄及有效位。不新增CAN查询、不改控制目标/故障条件/VM/看门狗。
- WF1默认200ms一次，沿用USART1现有完整帧发送仲裁，优先级低于主状态/故障，忙时不等待、累计丢帧。运行后保留约1秒尾迹；无运行记录时不持续发WF1。

## 日志与时间的含义

| 数据 | 来源/单位 | 分析边界 |
|---|---|---|
| WF1 acknowledged_decirpm | 对应轮最近收到成功应答的目标，带符号0.1RPM | 不是正在规划/排队的目标，也不是机械已到速 |
| WF1 measured_decirpm | 实际CAN速度回复，带符号0.1RPM | 四轮异步；不是四轮同一瞬间采样，不是小车地面真实速度 |
| WF1 ack_ms | 主控软件处理成功命令应答的毫秒时刻 | 不是驱动内部控制生效的硬件时间戳 |
| WF1 sample_ms/age_ms | 主控收到成功速度回复的时刻和该快照内年龄 | 不称电机内部采样时刻；有效位0时旧值只供追溯 |
| PM1 raw/sign/sample_ms/age_ms | 各轮原始位置、符号、回复时刻、年龄 | 不强行拼成同步位置，不以编码器里程冒充外部定位真值 |
| TM1 yaw/error/rate、距离目标/进度 | 已有航向/距离运行状态 | 使用source_valid和age；查看对应版本单位，RPM字段可能为0.1RPM编码 |
| OD1/OP1 | 已有里程/端点观察 | 局部参考不等于比赛地图绝对坐标；不恢复被观测不到的滑移 |
| HF、批次帧 | 首故障快照、生成/发送/应答及结果 | 失败也保留；不因停止后正常就覆盖首次异常 |
| PC UTC与monotonic_ns | 收到这一批串口字节的电脑时间 | 同批字节会共用接收时间；不是主控采样时间 |

离线重放时重新产生的PC接收时间只是重放处理时间，不能替代原现场时间。重放仍保留帧内主控时间。序号缺口说明观察记录不连续，不能直接归因无线丢包，也可能是主控忙丢观察帧；结合WF1/TM1丢帧计数和原始字节判断。重复、乱序、时钟倒退分别标记，不补造数据、不默认全是主控复位。

WF1字段顺序：`seq,tick_ms,session,active,state,dry_run,speed_valid_mask,ack_valid_mask,telemetry_dropped`，然后轮1～4各5项：`acknowledged_decirpm,measured_decirpm,ack_ms,sample_ms,age_ms`。使用CRC16-CCITT，初值FFFF，覆盖CRC前最后一个逗号在内的ASCII内容，末尾4位十六进制CRC及CRLF。valid mask低4位对应地址1～4；dry_run时两个有效位均为0。ack_valid_mask表示该会话记录中已有真实应答，可能是历史应答；必须结合active/state/tick/age使用，不把它当运动许可。

## 现场使用

从仓库根目录运行，COM号替换为无线接收模块实际端口：

```powershell
python "工创赛/scripts/vehicle_uart_capture.py" --port COM5 --stage 1
```

先打开采集，再用车上按键运行已确认的单阶段程序。采集器本身不会发车，也不发送心跳。本地第一阶段候选使用PC13且免电脑KEEP；但该候选尚未下载，板上旧升降调试程序不能按此流程直接开跑。下载并核对新版本后再按第一阶段说明验收；八段总调度尚未完成。阶段1～8分别修改 `--stage` 标签；Ctrl+C只结束采集，不向车发送停止命令。控制停止必须走固件自身的按键/故障/硬件急停。

首次使用如提示缺少serial模块，需在运行脚本的Python环境安装pyserial；离线重放不依赖pyserial。

默认输出 `工创赛/evidence/vehicle-stage/日期时间/`，含：

- `uart1.raw`：完整原始字节，包括坏帧/开头残帧/末尾截断；不可用解析CSV替代它。
- `frames.jsonl`：时间、原始偏移、分类、CRC/格式错误、序号质量标志及解析字段。
- `协议_字段版本.csv`：CRC/格式通过的结构化数据；重复/乱序/时钟变化仍有标记。TEXT表不是通过CRC验证的控制数据。
- `manifest.json`：本地HEAD、USER/HARDWARE/SYSTEM源码和工程文件哈希、端口/速率/人工阶段标签。不是板上固件自动证明。
- `summary.json`：原始字节SHA256、错误/缺口/重复/乱序/时钟倒退、退出原因。正常关闭会同步原始文件；进程或断电异常仍可能损失最后缓冲，不能承诺绝不丢数据。

离线重放示例（输出目录必须是新目录，避免覆盖原证据）：

```powershell
python "工创赛/scripts/vehicle_uart_capture.py" --replay "某次日志/uart1.raw" --stage 1 --out "工创赛/evidence/replay-example"
```

115200/8N1的线速理论上限约11520字节/秒，不等于无线模块实际吞吐。先测帧间隔、反馈样本变化率和丢帧，再决定采样/回传频率；不能仅把日志周期改小就宣称能辨识更快动态。后续模型拟合与验证使用不同实车趟次，并记录载荷、电压、轮胎/地面、起点、方向和参数版本；外部尺量/视频与编码器模型分开。

规则核对：R RUN-01（自主运行）、PWR-01（供电）、FIELD-06（路径包络）；E RUN-06/LOC-03。日志与采样频率为工程E，不是新增规则。福建正式时限仍待附件2-2核对。
