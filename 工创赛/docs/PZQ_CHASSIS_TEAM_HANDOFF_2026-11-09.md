## 给底盘同学的接口与分工

不要把pzq的完整`main.c`、`safety.c`、`can.c`或参数文件整批覆盖你的底盘工程。pzq副本包含历次平台集成改动，需按模块对比迁入；完整副本先用来复现已验机械基线。你维护底盘、定位、路线发布和公共资源；机械模块保持pzq的已验动作参数/时序，后续必要改动单独验证。

| 层/文件（pzq工程内） | 现有实现 | 接底盘时要做什么 |
|---|---|---|
| `CHASSIS/USER/main.c` | 原`App_CanTask`唯一拥有CAN收发，调用`Integration10_Service`、机构与底盘服务 | 保持单owner，不新增并发FIFO读取或第二个发电机任务 |
| `integration13_immediate.inc` | 已验固定下/左/右三件链；IT16一次启动 | 保留动作时序；正式模式需改由真实使命/视觉目标驱动，不从电脑Watch启动 |
| `integration10_complete.inc` | IT14接近、IT15回升/回收/回槽，IT9停止；真实视觉USART6解析与任务接口 | 现固定姿态动作不等于视觉选择已接通；不要造观测/库存成功 |
| `vehicle_source_parallel.inc`、`source_parallel_flow.c/h` | 三轴批处理、分段放行、真实完成、故障和STOP重试 | 保留实际反馈门槛与各轴停止出口；共享CAN不得另设裸写入口 |
| `vehicle_mission.h` | `VehicleMission_ReadAlignmentRequest`、`VehicleMission_ReadSourceTask`等现有请求接口 | 提供本轮run/阶段/坐标版本、真实扫码任务；到位后正确进入原料区阶段 |
| `source_stage2_body_port.h/.inc` | `Stage2Body_Configure`、`Stage2Body_GetHooks`、底盘纠偏/第三段队列框架 | 填入真实标定/车体/路线profile，执行纠偏并以新观测确认，不填默认有效位 |
| `source_stage2_backend.h/.inc` | `alignment_begin/poll`、`route_begin/poll/stop`、`path_verified`等既有hooks | 接真实底盘动作/状态；route请求和arm动作可同批发布，未完成实车验证 |

具体握手顺序：

1. 底盘进入原料区、停到视觉可识别和机构可达位置；后续以真实A模式/有效毫米标定纠偏，保持车身。项目坐标约定X向右、Y向前、单位mm；实际相机到车体的轴向与符号必须用新数据核对，不从画面像素直接生成电机量。
2. 视觉确认底盘对准且本轮标定/位姿有效，再按任务颜色选择新鲜物料实例和区域。色号、区域、槽号、两批任务不可混为同一索引。已验pzq固定顺序只说明三条机械路径，正式抓取顺序必须跟真实扫码任务。
3. 把经确认的区域/姿态交给pzq机械动作层，以其“接近重叠→提前闭爪→回升/回收重叠→回槽→松爪200ms”的时序执行。已有`Vision_SetTask`、`Vision_TakeTaskTarget`/USART6链和stage2接口供接续，但当前没完成颜色/实例到pzq三件链的端到端绑定。
4. 真实抓放证据提供者/库存账本确认三件已装载再离区。舵机PWM、CAN ACK、计时结束、`g_it_auto_state==2`均只是相应软件状态，不直接等于三槽库存有效。
5. 用户希望第三件松爪后底盘立即接第三段、4310边走边回0°。当前pzq看护链仍检查底盘不活动，**直接同时发底盘会被门禁停止**。必须改用/完成原route-and-stow分支与真实路线hooks，检查行驶扫掠后再验收；不要删除`!g_chassis_auto_active`来伪装衔接完成。当前新增200ms松爪时序须在正式接续中保留，底盘开始时点与实际放稳证据一起确定。

USART6实际接口是PC6/PC7、115200/8N1；4310在CAN2，升降地址5、伸缩地址6在CAN1。具体接线/驱动配置以本次硬件和源码为准，不能按别的工程名套参数。
