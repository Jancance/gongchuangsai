## 1. 当前生效架构

雷达TX/RX → 独立USB转3.3V TTL模块 → 香橙派USB；稳定5V给雷达供电，双方共地，外部供电时不并接转换模块5V。依据本包下位机开漏TX说明检查是否已有4.7kΩ上拉到3.3V，不重复堆叠或上拉5V。模块型号/端口及实测电平在接线时登记。

香橙派负责雷达握手/选区、扫描事务、COBS/CRC解析、障碍/方格/路径结果、地图有效性、导航与日志。STM32继续负责底盘控制/HWT和定位执行侧、雷达180°升降/ULN2003转向及反馈/互锁、最终运动许可与失联处理。P1/P2链路与雷达链路使用独立串口通道。

雷达工作包仍由电控组主导协议及机构联调，香橙派端与视觉/导航程序协调；硬件连接端改变不自动改变两组已确认主责。原USART3 PD8/PD9直连雷达由历史方案转为预留，不改PCB、不把它与USB-TTL的TX并联。若将来选其他物理接法另记变更。

## 2. 例程怎样复用

来源：D:/新建文件夹4/radar_stm32例程.zip；适用固件1.35/协议6/Flash保存状态11。复用link_protocol与radar_client的帧格式、字段、校验/分块/序号、状态机、超时和六种Demo业务语义，使用Python串口实现或适配可在Linux运行的客户端；具体语言模块在实施时冻结，不把HAL源码直接运行或烧到香橙派/雷达上。

HAL UART/DMA/HAL_GetTick/关中断及main初始化不移入Linux；改为独立串口服务、接收缓冲、有界发送队列、单调时钟与错误重连。客户端唯一调用者处理所有请求/状态；视觉推理和日志不得阻塞收包/心跳。结果按值复制并带版本/新鲜度，STOP独立优先通道；5秒雷达重连不能替代整车更快的失联停止。

## 3. 开局扫描、规划与行驶

### PA1起点输入（2026-10-23用户确认恢复）

起点由STM32读取已接好的PA1保持型两档开关：PA1低电平=start_id 1，PA1高电平=start_id 2。按原接线PA1经10k上拉3.3V、10nF对地，开关公共端接GND、其中一触点经1k接PA1、另一触点不接；实物COM及两档标签仍须通断/电平核对。旧“跳过PA1/由香橙派人工配置起点”由本次决定替代，不改PCB。

准备阶段定时扫描去抖，候选稳定50ms后显示/回报pending_start_id；上电前和上电后均可切换。检测到切换立即撤销稳定资格；切换过程中启动不缓存，提示重新触发。收到新的有效PC13启动事件时锁存active_start_id和run_id，进入准备流程，不能据此直接视为运动许可。

STM32向香橙派同步本轮start_id、run_id及配置/地图/标定版本，香橙派加载对应初始位置/朝向和路线，并调用雷达RequestSelectZone(1或2)。必须确认成功ACK、匹配区域HELLO与保存状态，向STM32返回匹配本轮的准备结果；失败/超时/旧回执不得启动后续行驶。区域的保存位姿是配置/标定值，不是实时测得的车位。

本轮使用同一active_start_id完成返程；启动后切换PA1不改变起点、位姿或路线，下一轮经明确准备复位后才重新采样。控制器重启不自动恢复运动。当前单输入上拉方案断线也可能表现为区域2，不具断线识别能力，不能声称已检测出开关拔线。

验收覆盖两档电平、两档分别上电、上电后切换、切换时启动、运行中切换、控制器复位、错误区号/迟到回执及双起点同区返回。PA1初始化/去抖、两端同步载荷、现场显示/标签与实物行为均待实现/验证；保留现有PC13及当前开发测试模式，不在本次文档更新中修改真实固件。

按合规启动/展开时机执行：锁存抽签start_id及设备profile → STM32升降/转向到已标定扫描姿态并确认底盘及机构停稳 → 香橙派握手、确认实际区域/标定 → 请求一次完整方格扫描 → 校验完整结果并核对保存状态 → 建立本轮地图版本 → 结合任务和有效当前位置规划各段 → STM32执行经过验证的轨迹。

- GRID_SCAN/RequestGridScan（SINGLE_MEASURE）进行14圈方格扫描，保存供雷达PLAN_PATH使用的结果。不得周期性反复触发写Flash。
- SCAN_ONCE/RequestScanOnce（SCAN_LOCKED）返回完整障碍坐标、方格与置信度，不保存路径规划使用的方格记录。需要更精细坐标时另安排该扫描，不能误当已经更新规划地图。
- PATH/RequestPlanPath只依据已有有效方格及雷达预配置布局规划，不能自动扫描。返回status=0才成功，waypoints不含起点、含终点；返回为空也须区分起终点相同与错误。
- 单纯ACCEPTED/ACK不是完整扫描完成；数量0只有完整有效时才代表本次未检测到障碍，超时/遮挡/缺包不能当空场。
- 雷达路径是方格节点，尚需核对布局/坐标、灰色车道、整车扫掠、误差及制动余量，转换为受限速度/连续曲线后执行。不要默认每格480mm或返回节点就是最快/可直接执行的轨迹。

## 4. 何时可以不重新扫描

工程目标：本轮开局扫描一次，满足下列条件后，允许同一地图多次请求不同工位之间的路径；不要求每到一格或换一个目标就重扫。

1. 扫描完整且覆盖需规划区域，实际标定与姿态正确，黑障/遮挡及漏检实测通过。
2. 雷达方格布局、永久障碍/通行设置与项目地图一致；实际起终点来自当前有效定位和任务，而非写死的示例编号。
3. 障碍和场地保持不变，行驶中的环境复核没有发现矛盾，位置与航向仍有效。

地图保存map_revision、run_id、zone/profile、安装/标定版本、扫描序号、完成时间与覆盖/完整性状态。Flash的grid_result_valid仅证明有保存记录，不证明它对应本轮场地；不得上电直接把上场记录当作新图。

障碍可能移动/新增、发现新障碍、漏扫/遮挡/溢出、重布场、扫描机构/标定变化或数据关联不明时，暂停使用原图，先按已验证策略停车/取消，再重新确认环境并生成新图。仅目标工位改变且图仍可信时可只重新规划。仅定位丢失时先恢复定位，不把重扫障碍图当作已经恢复X/Y。

本协议位姿/区域有使用范围，当前仅有静止标定扫描方案；地图失效后从可达安全处回到已验证扫描姿态或建立新的可用标定，再扫描。未验证任意路段扫描、运动去畸变及全场动态定位，不能直接一边走一边转雷达合并数据。

持续定位与必要环境复核贯穿行驶。HWT航向、轮速反馈/待验证X/Y估计及视觉纠偏仍需独立验收；一次障碍扫描不提供车辆随时间变化的位置，也不能保证所有后续路径一直可通行。

## 5. 挂入原阶段与现场调试

- 当前底盘/航向调试继续，不能因本次决定回退已通过项或跳过当前控制应答故障。
- 阶段5：雷达升降/转向/固定/零点/扫描高度前置检查，香橙派USB-TTL连接、区域/profile标定与实际14圈扫描。
- 阶段6：原F407雷达解析工作改为香橙派客户端移植和单独服务；验证协议/超时/队列/重连/旧结果拒绝及串口与相机并行。
- 阶段7：香橙派请求姿态，STM32回报到位/停稳后才扫描；完整结果后建立地图就绪状态，任何一步失败不误报成功。
- 阶段8：将真实地图、任务目标与有效位姿接入路线执行，验地图复用、多起终点、地图失效和重扫；再与搬运及双起点返程整合。保留最终使用教学、配置恢复与一次完整自主模拟。

现场需能读回串口/设备/profile/zone、扫描状态与错误、地图版本/有效性、路径起终点/状态和拒绝原因；提供允许调试时段的单项连接/扫描/规划检查及日志导出。运行期调试写入口与正式比赛入口隔离；不在赛后两行统计页增加诊断项。
