# 160 cm/s 四向底盘试验

以无雷达 v1.1 本地基线 `ec1bfa65` 为起点。四向分别跑，首轮只验正向。每次从静止起步，发出以 160 cm/s 为峰值的规划曲线。名义停点为 1664 mm，1920 mm 是路线边界，预留 256 mm 给实测停车误差。车载转速反馈和编码器差分估算电机/轮缘速度，实车地速不能由此单独确证。

## 轨迹与驱动单位

- S 曲线按 80 ms 批次取 3/5/3/2/3/5/3 个周期。加速度上限 2500 mm/s²，加加速度 10416.7 mm/s³。参考持续 1.92 s，名义停点 1664 mm，留 256 mm 考察实际停车误差。
- 77 mm 轮径的正向、反向或横移，轴向 1600 mm/s 对应约 396.85 rpm。现用 Emm 0.1 rpm 档需要原始值约 3969，超过协议上限 3000。整数模式对应约 397。整数模式实物车轮能力、航向修正余量和物理停止位置仍需实测。
- 测试程序通过厂家 `0x1A` 只读状态逐台核对 Emm 闭环整数 rpm。任何驱动不符合条件时，不发送运动命令；程序不写驱动设置。四台当前设置在本次任务中未实际读取。此后若现场切换输入模式，切回旧固件前先恢复并核对原设置，同一个原始速度数值在两种模式下相差 10 倍。

## Modes

在顶层参数 `3.stm32f407工程/USER/vehicle_parameters.h` 设置 `VEHICLE_SPEED_TRIAL160_MODE`。默认 `0U` 保持 v1.1 行为，`1U` 进入 VM setup-only，`2U` 启用速度轨迹。方向使用 `VEHICLE_SPEED_TRIAL160_DIRECTION`，0 前进、1 后退、2 左移、3 右移。用当前 Keil 工程的 `Vehicle_Integrated` target 编译。

当前四台驱动的 `S_Vel_IS` 为启用状态，也就是 0.1 rpm 输入。运动试验目标需要整数 rpm，运动入口只接受四台官方 `0x1A` 状态字均满足 `(word & 0x0086) == 0x0006`，分别表示 Emm 固件、闭环、关闭十倍输入。读回 bit 7 为 1 时，运动模式保持拒动。

模式 `1U` 下，第一次 PC13 只请求现有安全 Prime 和 VM 电源，底盘保持零速并轮询 CAN 状态、轮速反馈和四轮 `0x1A` 状态字。设置不符或读回错误会记录状态，VM 保持请求，供现场人员手动修改驱动选项。该模式不进入 `Zone2Begin`，也不会提交速度批次。第二次 PC13 撤销请求，由现有 Safety 流程关闭 VM。设置时发生真实 CAN、驱动、安全或 RTOS 故障仍会触发现有停机保护。模式 `1U` 不会自动衔接运动模式。

四轮均回读整数模式后，关闭 VM 并将模式改为 `2U`，再运行运动测试。模式 `2U` 要求原始 ICM 采样任务并保留原导航、安全和停车流程。回到普通 v1.1 模式 `0U` 前，现场必须先将四台驱动的 `S_Vel_IS` 恢复为启用状态，原始运行指令的物理转速会随该设置改变十倍。

## 离线 MATLAB

在本机 MATLAB 运行 `validate_speed_trial160`。2026-11-22 R2020a 实际通过四轴速度符号、零起零停、整数/小数命令边界和逐轮错相模型。20 ms 错相、80 ms 平均的理想整数模型得到约 1600.6 mm/s 峰值、1664.1 mm 停点和转入地面坐标后约 0.7～2.1 mm 的最大横向位移。该模型使用即时跟随的轮端，地速、带载滑移、CAN 时间波动、停车拖尾和惯导质量以现场数据为准。

## C 离线轨迹输出

在仓库根目录运行 `& './工创赛/tools/chassis-speed-trial-160/run_speed_trial160.ps1'`，使用本机 MinGW GCC 编译真实的底盘逆运动学，生成四方向共 100 行参考样本。CSV 的整数候选速度是同一时点四轮量化后的运动学估计，逐轮 20 ms 错相另看 MATLAB。候选整数值不能证明驱动已经配置或接收。

## 停稳偏差记录

每趟停稳后记录相对目标点的偏差，不要求加装测速仪。统一按本次行进方向建坐标。正的前后误差表示超过目标点，负数表示欠距；正的左右误差表示偏向行进方向左侧，负数表示偏右。先逐方向做三趟，再分析均值和重复性。输入 CSV：

```text
run,direction,forward_error_mm,lateral_error_mm
1,forward,12,-5
2,forward,9,-7
3,forward,14,-4
```

- 从本目录运行 `python summarize_offsets.py offsets.csv`。按方向输出前后和左右误差的均值、样本标准差，以及用于下一趟对照的反向补偿候选值。不同方向分开统计，不直接混合。
- 测试日志中的 ZDT 转速回报、编码器位置差分、HWT 角度和 ICM 原始数据可相互对照。它们不能单独确认车体地面距离、最大途中侧偏或轮胎打滑。停稳后按目标点测前后和左右偏差，单次偏差只记录，不立即改四向参数。保持起点、停车目标和载荷一致，先完成每方向三趟。
- 用同一份串口记录比较编码器位置差分和驱动回报转速：`python analyze_wheel_trace.py run.log`。差分使用相邻 `T160_W` 位置计数和各自回复时间，按 65536 计数/圈换算平均 RPM 与轮缘速度，不增加 CAN 查询。首个样本没有差分结果，低采样、缺样或回包延迟会影响速度估计，应按输出的实际采样间隔判断。
