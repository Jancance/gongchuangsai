## P1 本机 MATLAB 验证速度过渡和制动

实现前先冻结一个同函数输入可回放的 MATLAB 算法。输入包括当前**已兑现**的车体速度 `q0=[vx,vy,wz]`、加速度 `a0`、期望目标速度 `q1`、实际批次间隔、轮/姿态反馈及年龄、限制、到下一需停车位置的沿程余量和可用横向空间。三轴共享一条时间轴。平移和旋转分别使用 `mm/s` 与 `rad/s` 及其时间导数，按真实轮端映射检查联合约束，禁止把两种单位直接合成范数。

1. **单条速度曲线。** 用三次 Bézier 表示从 `(q0,a0)` 到 `(q1,0)` 的速度过渡，控制点 `[q0, q0 + T*a0/3, q1, q1]`，`s=t/T`。对速度控制点分别施加 `D=3*diff(P)/T`、`J=2*diff(D)/T` 得加速度、jerk 控制点。车体平移分量绝对值各≤400，平移 A/J 用二维范数，角向单列，`W` 由实际 `Chassis_Inverse` 的未缩放矩阵确定。对 P/D/J 映射的四轮控制点逐一验限。必要时固定次数 de Casteljau 细分后再用凸包证界，降低单段控制点过松导致的假拒绝。T 搜索限定范围与次数。最短稳健候选进 MATLAB，并冻结搜索顺序、细分、量化和浮点容差，C 与向量同轨。候选起始值平移150mm/s²、300mm/s³，角向90°/s、180°/s²、1440°/s³。逐轮 A/J 取自工程证据或公开为灵敏度假设，保留300RPM/0.1RPM编码边界。
2. **在实际坐标合成限速。** 路径给世界系期望切向和有界横向速度，按当前有效 heading 变换到车体系。把原 `HeadingController_HoldStep` 的轮差 RPM 按实际轮端几何还原成 `wz`，旋转段沿冻结绝对目标及方向给 `wz`。联合检查 `Wq`；必要时共同缩放平移，保留实际 heading 预算，连同比例变化一起经上一步曲线。限定 `Chassis_Inverse` 的缩放结果必须为1，并在编码前验四轮。保留无纠偏长直线速度400、对角线400+400目标，用短段制动、轮端不足或横向回线案例证明可达速度随约束变化。
3. **每次提交前保有制动解。** 用同一速度曲线 `q1=0` 从当前 v/a（含迟到观测和旧批最大持令）生成停止候选。用 `T/4*sum(hypot(Px,Py))` 保守限住平移弧长，并把按进度管道投影的横移/偏航包络、反馈速度与指令差、源迟延及四轮发帧混合窗口分别纳入。角停止同样核剩余锁定方向角和旋转包络。试发布下一命令前验证该前缀及其后仍可制动。制动可行时提前切已核轨迹并连续执行到零；正常变化从兑现边界重定时，a 继承，不在每个采样或过角归零。无可行运动候选时复用此前仍有效的停车计划；假设已破坏时走既有严重故障 STOP。零目标到达后另等实际 STOP/反馈证据。
4. **独立模型输入和跨批次断言。** 批次边界锁存四轮同一代速度，按实际 Tx/ACK 先后逐轮保持，区分成功、晚回、应答丢失且可能已施加。浮点曲线约束与0.1RPM阶梯指令分开断言，ABI 输入冻结区分理想同步曲线、混合持令及量化裕量。四轮全收后推进命令状态；局部失败禁止继续使用完整新向量的假设。源断样、反向、横移穿零、PD突变、t回绕、窄段、a非零/车速边界、长停和90°/180°欠转均要跑。记录模型的每一步决策、v/a/j、T、最终四轮方向/量化值、停止距离上界和失败原因；出具可直接喂给实际 ARM C 的输入/预期表。

P1 只接触模型与前置证据。P2 用实际 owner 验证命令兑现时序、自动停稳和 C 数学同轨。P3/P4 各自先验几何及全线数值，验证过角过程中切向、横向、角向约束同时成立。轮速/HWT 时延或总线最坏参数缺乏实测时，在模型中标识范围和失效边界。

## P2 接入唯一 CAN owner，验证停稳和速度兑现

1. 保留原 CAN 任务、原 Safety 和 `ChassisAuto_CanStep`。在 `AppChassis_CanStep` 的导航 profile 中，以单一分支取代本次不用的 Combined、Heading、StartupAxes、VehicleArm 与调试发送分派；实际事务仍走 `chassis_auto_test.c` 的发送、应答、反馈和 STOP。Key/TaskA 只交请求，RadarTask 只交数据。每轮 CAN service 仍给监督/停机留事务时隙。默认旧 profile 回归，导航候选显式 `ICM45686_SAMPLE_ONLY=0`、baseline40 采集关闭、连续里程计开启。
2. 最小接口是按值传递的一份导航输入和一份批次回执。输入绑定 run/session、递增 generation、样本身份、有效时限及四轮编码；原 owner 在批首锁存、批中不换代，发布实际 send/ACK 时刻、掩码、失败地址、最近完整批与可能已施加的轮。制动或取消可打断，迟 ACK 不推进已取消会话。在临界区外用 P1 数学试算、入队前核对身份/取消/失效；根据完整批的时间边界推进曲线，从已兑现 v/a 接续。有界异步持令、量化及追随误差使用与 P1 相同的合同，超出证据范围不继续发下一非零批。保留现有严重故障 STOP。
3. 用原 HWT yaw/rate 各自的真实时间、四轮实测速度和位置、当前供电 epoch，形成一致观测。逐轮按 `Chassis_DriverFeedbackToLogical → Chassis_Forward` 转换，位置用连续地图 corrected，raw 差分保留 ESTIMATED。四向沿已确认50%候选，轻微纠偏仅应用一次，真正斜移/转向不用纯轴经验系数。收拢后同 owner 先上电空闲采集四轮和 HWT，`AppOdometry_MapStep` 在 backend 未 active 时建立本 run 基线，再允许首个非零批。站间保留地图与正常供电，带电空闲期间继续轮询，严重故障沿原策略处置。
4. 站停证据绑定 run、session、stop epoch，四轮 STOP 回复、随后各轮新速度和新 HWT 角速度均合格，再核站点位置/绝对航向；新非零命令、换会话或过期使证据失效。验证冷启动、长停重启、旧 STOP 混入、陈旧单轮、部分批次失 ACK、取消、反馈倒序和 VM 切断。实际 `HeadingController_HoldStep` 的有符号轮差经实际几何计入总预算，原地转向使用锁定绝对航向和转向，原普通低速路径保留。
5. 先验收 P1 最终 MATLAB 输入与 SHA，再验真实 M4F C 与同组向量。特别核 `fusion_reference.c` 的 Prepare 沿程限值、Step 实测合速判定和 world 输出合速裁剪三处，按当前 heading 换算车体分量预算并计横向/航向纠偏。分别给出足够长度的纯轴400和斜行400+400、短段提前降速并停到站的峰值和轨迹。原应用上限300 RPM及0.1 RPM编码保持；汇报模型可达峰值、发送值、设备模拟测量三列。

短段验收预先冻结终点/位置公差，从静止出发逐批追踪剩余距离并重新判断制动；结束时核停点误差和用时。另设仅空间足够的长段上限检查。仅用离线拼接的加速/制动曲线或只证明“停在一片可用空间内”，不足以覆盖正常可到站这一项。验证在目标附近仍有非零延迟/误差裕量时不会无限等待。

## P4 在可行场角连续过渡

现 reference 对非共线节点把速度帽置零。保留原轨迹身份，增加固定航向的 LINE→BLEND→LINE，按相邻段可用长度裁前后两端，用一条五次 Bézier 圆顺通过。两端控制点使切线与直线一致、曲率归零，曲线内使用单调弧长进度和切向；不在换元处清空速度、加速度或PD。冻结允许几何和空间误差后，先在本机 MATLAB 证明各方向的连续扫掠与有限段长度。用控制点凸包细分覆全区间，并验证曲线误差、延迟跟随余量和制动走廊。速度同时受法向加速度、曲率导数产生的 jerk、切向加减速、车体分量与逐轮 P1 预算约束；提前减速进入，不要求所有角都达到40cm/s。

正常四种场角、双向进出、邻角过近、中央路口预减速、边界与占用冲突均留独立用例。合格场角需有持续多个批次、明显高于停稳阈值与测量量化的实际模拟过角速度，heading 保持，内外接点切向连续，STOP计数不增、会话不重启。若本场八段样图未经过四角，另给穿越未覆盖场角的合法协议路径做回放；不把站点强制转向混记为场角。确有几何/动力学不可行时记录拒绝与沿用的停车出口，不能绕开障碍或用全停完成正常场角验收。
