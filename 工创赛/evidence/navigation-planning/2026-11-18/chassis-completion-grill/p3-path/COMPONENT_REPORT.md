# P3 区2有向路径转换

`zone2_nav_path.c/.h` 对雷达已完成的 GRID 和有向 PATH 建立本场身份约束，验证请求方向、事务序号、图代与重连代。缓存只复用匹配上下文的雷达回复，参考计划每段使用新的本地 ID 和当前实际位姿。按 `FieldMap_CellCenter` 逐格展开轴向压缩跨度检查占用和重复，再用原压缩中心节点和首尾连接生成参考。四块黄区及 283×254 mm 连续行驶/转弯扫掠由现有 `FusionReference_Prepare` 检查。雷达负责求最短路径，STM32 执行接收、校验与后续跟踪。绕障用例中的绕行路径来自模拟雷达输入。

区2 八段表和实际站点映射与 MATLAB 同轨。180° 输出默认 CW 的两次90°以及空间条件等价的 CCW 元数据，实际参考计划采用 CW。相同格有非零距离可校验同格连接，两点重合返回独立状态且无有效参考，交给上层判定停稳与适当终点。回区函数要求实际中心、航向、不确定度和独立停稳事实，检查完整外形在区内。

本机 MATLAB 的 95 项断言及模型边界见 `MATLAB_REPORT.md`、`p3_path_vectors.json`。实际 ARMCC Cortex-M4F 指令在 Unicorn 2.1.4 上完成 286 项检查，覆盖八段/六有向请求、同场缓存重入、占用/合法绕行、黄区、回区余量及失效输入。复现命令为 `python run_p3_arm_replay.py`。首轮因校验脚本把物理相同的 180° 和 −180° 直接比较而失败，证据见 `arm_first_angle_wrap.json`，最终通过回执见 `arm_path_replay.json`。

尚未接入 RadarObserver 实际数据发布、一键启动状态、CAN owner、停车证据或 P4 连续过角。实车定位误差、运动、时间和双目标构建由后续对应环节验证。无硬件操作。
