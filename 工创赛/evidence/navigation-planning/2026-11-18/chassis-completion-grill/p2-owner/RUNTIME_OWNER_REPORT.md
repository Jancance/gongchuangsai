# 区2 CAN owner 与单键入口验证

2026-11-18，基线 `e9471aff`。区2候选需显式选 `APP_ZONE2_NAV_ENABLE=1`、`APP_CONTINUOUS_MAP_ENABLE=1`、`ICM45686_SAMPLE_ONLY=0`，使用原模式3任务。默认区2候选关闭。

- CAN 任务按 80 ms 固定周期执行 8 个绝对 10 ms 槽，错过的槽不补发。0/20/40/60 ms 为四个 F6 轮端命令，10/30/50 ms 为轮询 43，70 ms 为独立 3A。四轮邮箱受理、实际 TX 和有效 ACK 分开记。四个有资格的及时 ACK 才推进代号，部分送达保留掩码和每轮时间。新代锁定预定绝对批首时刻。第一批要求四轮零速。
- 建立软件供电代后独立执行一次旧 3A，从环回切到正常 CAN 模式；该次查询不作为后续有界样本。Safety 继续使用真实独立 3A 和 43。正常 3A 门限 330 ms；单次实际丢失后，同地址仍轮转一次且允许使用原时间戳至 650 ms，收到新保护状态立即处理，连续两次丢失或过期停止更新运动命令。43 保持 130 ms 证据上限，缺包不续期。两类失败有逐轮计数。
- 去下一段先释放已成功的前一会话，再从当前实测位置准备新段。后端每段沿用 45 s 总截止、10 s 准备截止、500 ms STOP ACK 截止及 2 s 停稳截止。正常到站 STOP 的四个 ACK 确认后，每个轮的查询须在最终 ACK 后发起，随后至少 1 s 内其反馈始终为零转速，位置始终处于同一个有符号计数锚点的 ±1 原始计数内。77 mm 车轮一计数约 0.00369 mm。持续每次爬动一计数会重启停稳计时；该逻辑只构成轮端软件证据。内部换向使用零 F6 批完成后独立位速证据，站点还要核对导航层 HWT、地图和场地包络。
- 区2候选的 PC13 只请求导航，PA1 服务正常进行，雷达任务继续服务，但退出原自动 0→24 观察启动。原组合/串口诊断和机构手动启动不进入区2运行路径，保留观察器有界升降和原停止。保留 `AppChassis_SafetyCheck`、`Safety_Update`、看门狗和原故障分支。原组合测试空闲态写 VM 的路径在区2候选隔离。
