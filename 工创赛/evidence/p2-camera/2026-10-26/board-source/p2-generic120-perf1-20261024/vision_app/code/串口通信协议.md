# 视觉程序串口通信协议

本文档说明当前视觉程序与F407功能板之间的串口协议，包含视觉
模式切换、扫码任务码同步、物料抓取位置颜色，以及转盘中心、三圆环和
中环加长边码垛结果的上报。

## 0. 协议总览

模式控制帧使用 `AA 功能码 BB`；任务码同步帧使用
`AA 06 15字节ASCII任务码 BB`（固定18字节，不是模式切换）。所有视觉
应答使用 `CC 功能码 数据 DD`。当前完整模式关系如下：

| 视觉功能 | 模式号 | 进入/选择模式 | 连续上报 | 单次询问 | 视觉回传 |
|---|---:|---|---|---|---|
| Idle | `0x01` | `AA 01 BB` | 不适用 | 不适用 | 无 |
| 物料抓取 | `0x02` | `AA 02 BB` | 不适用 | 每条 `AA 02 BB` 启动一次周期 | `CC 02 LEFT RIGHT DOWN DD` |
| 普通三圆环 | `0x03` | `AA 03 BB` | 再发 `AA 14 BB` | 再发 `AA 15 BB` | 单帧 `CC 03 R2_X R2_Y ANGLE DD` |
| 中环＋双直线（键盘 `S`） | `0x04` | `AA 04 BB` | 再发 `AA 14 BB` | 再发 `AA 15 BB` | 单帧 `CC 03 R2_X R2_Y ANGLE DD` |
| 转盘外圆圆心 | `0x05` | `AA 05 BB` | 再发 `AA 14 BB` | 再发 `AA 15 BB` | `CC 05 X_L X_H Y_L Y_H DD` |

### 普通圆环与 `S` 模式的重要区别

普通三圆环和按 `S` 进入的中环＋双直线模式必须使用不同的询问模式号：

```text
普通三圆环：       AA 03 BB
中环＋双直线模式： AA 04 BB
```

不能用 `AA 03 BB` 同时表示这两种算法，否则视觉程序无法判断应当直接
识别三个圆环，还是通过中环和两条长边重建三个圆心。

两种模式的回传协议保持完全一致，均在一个 `CC 03 ... DD` 帧中同时
回传2号圆心和实际连线角度。这里应特别区分：请求中的 `0x04` 是中环＋
双直线的模式号，应答仍使用公共的圆环纠偏功能码 `0x03`，不应改成
`0x04`。

`AA 14 BB` 和 `AA 15 BB` 是当前已进入模式下的上报策略指令，本身不再
重复携带模式号。因此单次询问必须先明确发送 `AA 03 BB` 或 `AA 04 BB`，
再发送 `AA 15 BB`。

## 1. 串口参数

### 主程序的图像坐标选择

`main.py` 启动时读取 `code/config/camera_processing.json`：

```json
{
  "undistort_enabled": true
}
```

`true`（默认）使用相机标定参数进行畸变矫正；改为 `false` 后直接使用
原始画面，无需读取相机标定文件。修改后重启主程序生效，也可以通过
`--camera-processing-config 文件路径` 指定其他配置。

该开关统一影响主程序的预览、像素测量、视觉识别及回传坐标；窗口标题
分别为 `Undistorted Camera` 和 `Raw Camera`。串口帧格式保持不变。
下文中的参考坐标和毫米换算基于默认矫正画面，关闭矫正后需要重新核对
抓取区域、工位参考坐标和像素比例。独立标定工具仍使用原有矫正流程。

### 串口设备配置

| 参数 | 默认值 |
|---|---|
| Linux 设备 | `/dev/ttyS7` |
| 波特率 | `115200` |
| 数据位 | 8 bit |
| 校验位 | 无校验（N） |
| 停止位 | 1 bit |
| 流控 | 无 |
| 读写方式 | 非阻塞 |

默认设备、波特率和重连间隔统一定义在 `turntable_serial.py` 顶部的
`DEFAULT_SERIAL_DEVICE`、`DEFAULT_SERIAL_BAUD` 和
`DEFAULT_SERIAL_RECONNECT_INTERVAL` 中，`main.py` 直接引用。
以后修改默认串口只需要改这一处；启动时也可以临时覆盖：

```bash
python3 code/main.py \
  --serial-device /dev/ttyS7 \
  --serial-baud 115200 \
  --serial-reconnect-interval 1.0
```

## 2. 底盘发送给视觉程序

原有模式和上报控制帧为固定3字节（`0x06`任务码帧除外）：

```text
AA  功能码  BB
```

| 完整帧 | 功能 | 处理结果 |
|---|---|---|
| `AA 01 BB` | 返回 Idle | 停止所有识别和发送，清除检测历史、上报模式及待应答请求 |
| `AA 02 BB` | 启动物料抓取识别 | 进入 `MATERIAL_PICKUP`，清除旧结果并启动一次新的低速颜色上报周期 |
| `AA 03 BB` | 进入三圆环工位模式 | 进入 `RING_STATION`，保持静默并等待选择发送方式 |
| `AA 04 BB` | 进入中环加长边码垛模式 | 进入 `RING_STACKING`，由中环计算平移、上下长边计算角度，保持静默并等待选择发送方式 |
| `AA 05 BB` | 进入转盘识别 | 进入 `TURNTABLE`，但保持静默，等待选择发送方式 |
| `AA 14 BB` | 连续上报 | 作用于当前转盘、三圆环或码垛模式；稳定后逐帧发送结果 |
| `AA 15 BB` | 查询一次 | 作用于当前转盘、三圆环或码垛模式；获得稳定结果后只回复一次 |

程序启动时处于 `IDLE`。三圆环应先发送 `AA 03 BB`，中环加长边码垛
应先发送 `AA 04 BB`，转盘应先发送 `AA 05 BB`，再用 `AA 14/15 BB`
选择上报方式。物料模式不使用 `AA 14/15 BB`，每条 `AA 02 BB` 固定
启动一次上报周期。

控制指令和任务码同步均没有ACK帧。未定义的功能码会被忽略，留作后续
视觉模式扩展。

### 2.1 任务码同步：`0x06`，固定18字节

F407从扫码器取得本场任务后，按原始顺序把四组编号同步给视觉程序：

```text
AA 06 C1 C2 C3 2B R1 R2 R3 2B D1 D2 D3 2B S1 S2 S3 BB
```

其中帧头、功能码和帧尾是二进制字节；中间15字节为ASCII正文
`ddd+ddd+ddd+ddd`，不带回车、换行、字符串结束符、长度或CRC字段。

| 偏移 | 长度 | 含义 |
|---:|---:|---|
| 0 | 1 | 帧头 `0xAA` |
| 1 | 1 | 任务码功能码 `0x06` |
| 2～4 | 3 | 第一批颜色，ASCII `1`～`6`，组内不重复 |
| 5 | 1 | ASCII `+`（`0x2B`） |
| 6～8 | 3 | 第一批圆环号，必须是1/2/3的排列 |
| 9 | 1 | ASCII `+` |
| 10～12 | 3 | 第二批颜色，组内不重复且与第一批颜色集合相同 |
| 13 | 1 | ASCII `+` |
| 14～16 | 3 | 第二批圆环号，必须是1/2/3的排列 |
| 17 | 1 | 帧尾 `0xBB` |

例如任务码 `156+123+651+213` 的完整帧为：

```text
AA 06 31 35 36 2B 31 32 33 2B 36 35 31 2B 32 31 33 BB
```

视觉端在看到 `AA 06` 后等待18字节收满再校验。合法任务码会一次性替换
内存缓存，并显示在独立的 `Task Code` 窗口；坏帧不会覆盖旧任务码。
任务码只更新缓存，不改变视觉模式、上报策略、运动状态或待应答请求。
缓存经过Idle、模式切换和串口重连后仍保留，但程序重启后清空。本帧没有
应答，禁止自行发送 `CC 06`。

### 接收解析行为

- 支持一帧被拆成多次串口读取。
- 支持一次串口读取包含多个完整帧。
- 帧头之前的无效字节会被丢弃。
- 坏帧不会导致后续有效帧失去同步。
- 串口断开时会丢弃未完成的半帧，避免与重连后的数据错误拼接。

## 3. 视觉程序返回物料位置颜色

物料应答为固定 6 字节批量帧：

```text
CC  02  LEFT_COLOR  RIGHT_COLOR  DOWN_COLOR  DD
```

| 字节序号 | 字段 | 说明 |
|---:|---|---|
| 0 | `0xCC` | 帧头 |
| 1 | `0x02` | 物料抓取功能码 |
| 2 | `LEFT_COLOR` | 左抓取位置颜色编号 |
| 3 | `RIGHT_COLOR` | 右抓取位置颜色编号 |
| 4 | `DOWN_COLOR` | 下抓取位置颜色编号 |
| 5 | `0xDD` | 帧尾 |

颜色编号与公共 HSV 配置一致：

| 编号 | 含义 |
|---:|---|
| 0 | 该位置为空 |
| 1 | 红色 |
| 2 | 黄色 |
| 3 | 蓝色 |
| 4 | 绿色 |
| 5 | 黑色 |
| 6 | 浅蓝色 |

例如左侧为红色、右侧为空、下方为蓝色：

```text
CC 02 01 00 03 DD
```

物料流程固定为一次性上报：

```text
底盘完成摄像头抬升
底盘 -> 视觉：AA 02 BB
视觉：识别活动区内全部1～3件物料并跟踪速度
视觉 -> 底盘：CC 02 LEFT RIGHT DOWN DD  接近停稳后只发送一次
```

- 所有可见物料必须唯一进入左、右、下三个抓取区之一。
- 活动区内仍有物料未进入抓取区时不会把对应位置误报为空。
- 每次 `AA 02 BB` 后必须先连续两个有效测量帧达到 `30 px/s`，确认本
  周期确实发生过转动；如果进入模式时转盘已经静止，则始终禁止发送。
- 确认转动后，所有物料最大速度连续三个有效测量帧不高于 `25 px/s`，
  且位置颜色保持一致，才允许发送。
- 发送成功后保持 `MATERIAL_REPORTED`，不会重复发送。下一次抓取必须
  再发一条 `AA 02 BB`，这会清除旧结果并建立新周期。
- 串口写入失败不会消耗本周期；重连后必须由当前新鲜画面再次满足条件。

## 4. 视觉程序返回转盘中心

转盘中心返回帧固定为 7 字节：

```text
CC  05  X_LOW  X_HIGH  Y_LOW  Y_HIGH  DD
```

| 字节序号 | 字段 | 说明 |
|---:|---|---|
| 0 | `0xCC` | 帧头 |
| 1 | `0x05` | 转盘中心功能码 |
| 2 | `X_LOW` | X 坐标低字节 |
| 3 | `X_HIGH` | X 坐标高字节 |
| 4 | `Y_LOW` | Y 坐标低字节 |
| 5 | `Y_HIGH` | Y 坐标高字节 |
| 6 | `0xDD` | 帧尾 |

X、Y 均为无符号 16 位小端整数：

```text
X = X_LOW | (X_HIGH << 8)
Y = Y_LOW | (Y_HIGH << 8)
```

默认坐标来自畸变矫正后的 `1280×720` 图像；关闭矫正时来自原始图像：

- 左上角为 `(0, 0)`。
- X 向右增大，Y 向下增大。
- 单位为像素。
- 坐标来自转盘外圆拟合结果，不会直接回传三物料轨迹圆心；发送时按下述规则处理负值。
- 普通外圆搜索使用稳定窗口的中值；三物料种子与同帧外圆同时通过时，
  通过交叉验证后直接建立稳定状态。
- Python 浮点坐标使用 `int()` 截去小数部分，不进行四舍五入。
- X、Y 分别按 `max(0, int(坐标))` 编码，负坐标发送为 `0`；算法结果和稳定状态不受影响。
- 非有限数值及转换后超过 `65535` 的坐标仍拒绝发送。

例如中心为 `(320.9, 240.9)` 时，实际发送整数 `(320, 240)`：

```text
CC 05 40 01 F0 00 DD
```

例如识别圆心为 `(640, -13)`，实际发送 `(640, 0)`：

```text
CC 05 80 02 00 00 DD
```

发送记录保存实际编码后的坐标。本次仍使用 `uint16`；后续改为 `int16`
时需要同步修改下位机解析。此归零规则仅用于转盘圆心应答，圆环应答不变。

当前协议不包含长度字段、校验和或转义字节，底盘应按照固定 7 字节长度
解析返回帧。

### 4.1 当前视角的像素与毫米换算

2026-09-04 使用畸变矫正后的实时画面连续测量，300 mm 转盘的稳定外圆
半径中值约为 `303.04 px`，直径约为 `606.09 px`，因此当前固定视角下：

```text
1 px ≈ 0.495 mm
1 mm ≈ 2.020 px
```

串口仍然传输像素整数，不在视觉端换算成毫米。底盘如需把同一转盘平面上
的像素偏差换算为距离，可以使用：

```text
ΔX_mm = ΔX_px × 0.495
ΔY_mm = ΔY_px × 0.495
```

该比例只适用于本次相机高度、俯角和畸变矫正参数。相机姿态改变后必须
重新测量，不能继续使用 `0.495 mm/px`。

## 5. 视觉程序返回2号圆心和实际连线角度

当前协议发送检测得到的实际 `station_yaw_deg`。11字节帧长度不变，但
不能继续发送旧的 `correction_yaw_deg`，两者无法仅凭帧长度区分。

普通三圆环和码垛模式每次上报固定发送一个11字节帧：

```text
CC  03  R2_X_LOW  R2_X_HIGH  R2_Y_LOW  R2_Y_HIGH  ANGLE_BYTE0  ANGLE_BYTE1  ANGLE_BYTE2  ANGLE_BYTE3  DD
```

帧内的2号圆环中心：

- `R2_X`、`R2_Y` 默认是矫正后 `1280×720` 图像中的像素坐标；关闭矫正时为原始图像坐标。
- 两个坐标均使用无符号16位小端整数，并通过 `int()` 截去小数。
- 普通圆环模式的R2来自直接识别到的中间圆环。
- 码垛模式的R2来自直接识别到的中环。

帧内的实际连线角度：

- `ANGLE_BYTE0～3` 是 `station_yaw_deg`，单位为度。
- 数据格式为IEEE-754单精度浮点数（float32），小端字节序。
- 不是 `correction_yaw_deg`，也不是 `angle_error_deg`。码垛模式发送长边
  估计后的整体工位角度，不发送任意一条未处理的边线角度。

- 当前普通圆环和码垛模式共用的标准工位角度为 `0°`，即三个参考圆心
  水平排列；角度验收门槛为 `±1°`。
- 圆心和角度共用同一个帧头、功能码和帧尾。只有11字节完整写入成功，
  才认为本次单次请求已经完成。
- 只有视觉结果稳定并且实际连线角度有效时才发送，不发送零坐标占位、无效
  角度或旧结果。

例如2号圆心为 `(633.9, 321.9)`，实际连线角度为 `-1.25°`：

```text
CC 03 79 02 41 01 00 00 A0 BF DD
```

圆环双上报流程：

```text
连续：AA 03 BB -> AA 14 BB -> 每个稳定帧发送一个11字节帧
单次：AA 03 BB -> AA 15 BB -> 稳定后只发送一个11字节帧
```

单次请求在尚未稳定时会保留；重复 `AA 15 BB` 合并为一个请求。发送成功
后仍处于单次模式，但不会继续发送，直到再次收到 `AA 15 BB`。从连续模式
收到 `AA 15 BB` 会立即停止连续上报，并转为一次应答。

### 5.1 中环加上下长边码垛模式

码垛模式使用相同的“2号圆心＋实际连线角度”11字节帧。区别只在视觉
结果来源：

- `R2` 来自直接检测到的中环；已保存搜索标定时采用最外圈拟合，否则沿用原 Hough 圆及精修。
- 主程序允许中环配合上侧、下侧任意一条有效基准线运行；两侧均有效时，
  按线段长度加权计算 yaw；仅一侧有效时使用该线角度。
- `R1`、`R3` 根据中环平移和长边 yaw，由固定三环标定基准重建。
- 中环和至少一条基准线有效，并满足连续稳定要求（默认 3 帧）后才允许发送。
  单侧出界或没有合格候选时继续检查另一侧；两侧都有候选但方向冲突时，
  仍判失败，不随意退化为单线。
- 单双线切换不直接清空稳定窗口，仍需满足原圆心和角度稳定约束；完全
  丢失时清空历史并停止发送，待回复请求保留。未标定路径保留上一帧线
  的局部精修，但缺失侧清除种子，不把旧线当成当前有效观测。
- 界面和终端显示 `Lines=1 (TOP)`、`Lines=1 (BOTTOM)` 或 `Lines=2`，
  缺失侧角度显示 `--`。窗口失败提示使用英文，终端保留详细原因。

码垛双上报流程：

```text
连续：AA 04 BB -> AA 14 BB -> 每个稳定帧发送一个11字节帧
单次：AA 04 BB -> AA 15 BB -> 稳定后只发送一个11字节帧
```

对应的普通三圆环单次询问必须以 `AA 03 BB` 开始；虽然最终应答批次
相同，但这两个模式询问帧的模式号不可互换。

键盘调试时按 `S` 进入 `RING_STACKING`，按 `I` 返回 Idle。

## 6. 转盘的两种发送方式

转盘中心采用真实外圆的径向精修结果。画面中存在三个物料时，程序先用
三个物料底端拟合轨迹圆，只把轨迹圆心作为真实外圆的搜索初值；三物料
圆心不会直接上报。若同帧外圆质量检查失败，则该快速结果作废并转入全图
大圆搜索。最终通过 `CC 05 X Y DD` 发送的坐标始终来自真实转盘外圆。

当前转盘定位顺序如下：

```text
三个物料端面分簇 -> 选择三个底端 -> 三点拟合粗圆心
                                      |
                                      v
                            局部搜索300 mm真实外圆
                              | 成功          | 失败
                              v               v
                       采用外圆圆心      全图Hough重定位
                              |
                              v
                       后续局部外圆跟踪
```

- 三物料快速路径成功时，三个底端和真实外圆在同一帧完成交叉验证，结果
  直接进入稳定状态；下一帧开始只做局部外圆跟踪以保证帧率。
- 全图 Hough 路径需要连续累计当前配置规定的稳定帧后才允许发送。
- 已锁定外圆短暂丢失时不会发送三物料粗圆心，也不会发送旧圆心；程序
  会重新执行三物料快速定位或全图外圆重定位。

### 6.1 连续上报，供底盘 PID 使用

推荐指令顺序：

```text
底盘 -> 视觉：AA 05 BB    进入转盘识别
底盘 -> 视觉：AA 14 BB    开启连续上报
视觉 -> 底盘：CC 05 ... DD
视觉 -> 底盘：CC 05 ... DD
视觉 -> 底盘：CC 05 ... DD
              ...
底盘 -> 视觉：AA 01 BB    完成后返回 Idle
```

只有 `detected=True` 且 `stable=True` 的新鲜检测帧才会发送。当前摄像头
目标帧率为 30 FPS，因此稳定跟踪时通常接近每秒 30 帧，但实际频率以
视觉处理帧率为准。

识别暂时失败或稳定窗口尚未满足时停止发送，不发送零坐标，也不重复旧
坐标；恢复稳定后自动继续连续上报。

### 6.2 请求一次，供单次坐标映射使用

推荐指令顺序：

```text
底盘 -> 视觉：AA 05 BB    进入转盘识别
底盘 -> 视觉：AA 15 BB    请求一次中心
视觉 -> 底盘：CC 05 ... DD  获得新鲜稳定结果后只回复一次

底盘 -> 视觉：AA 15 BB    需要新坐标时再次查询
视觉 -> 底盘：CC 05 ... DD

底盘 -> 视觉：AA 01 BB    完成后返回 Idle
```

收到查询时如果中心尚未稳定，视觉程序会保留一个待应答请求，等下一次
出现新鲜稳定结果后回复。应答成功后保持请求模式，但不会继续发送，直到
再次收到 `AA 15 BB`。

中心稳定前连续收到多条 `AA 15 BB` 时只保留一个待应答状态，不累计多次
回复。从连续模式收到 `AA 15 BB` 后，会立即切换到单次请求模式，完成一次
应答后停止发送。

## 7. 模式状态

```text
                  AA 05 BB
       IDLE ----------------------> TURNTABLE / WAITING
         ^                                  |
         |                                  | AA 14 BB
         |                                  v
         |                         TURNTABLE / CONTINUOUS
         |                                  |
         |                                  | AA 15 BB
         |                                  v
         +------ AA 01 BB -------- TURNTABLE / ON_REQUEST
```

- `WAITING`：执行当前视觉识别，但串口不发送中心。
- `CONTINUOUS`：稳定有效帧逐帧发送。
- `ON_REQUEST`：每个请求最多应答一次。
- 重新发送 `AA 05 BB` 会恢复 `WAITING`，并取消旧的连续模式或待应答请求。
- 三圆环使用 `AA 03 BB`、中环加长边使用 `AA 04 BB` 进入；两者状态
  规则都与转盘模式一致，并共用 `AA 14/15 BB` 选择连续或单次上报。
- 物料使用 `AA 02 BB` 进入 `MATERIAL_ARMED`；发送成功变为
  `MATERIAL_REPORTED`，重复 `AA 02 BB` 会重新回到 `MATERIAL_ARMED`。
- 任意识别模式收到 `AA 01 BB` 都会返回 `IDLE` 并清空所有待上报状态。

## 8. 串口异常处理

- 串口打开或读写失败不会终止摄像头和视觉识别。
- 默认每 1 秒尝试重新连接一次。
- 连续模式在重连后使用新的稳定帧恢复发送。
- 单次模式的待应答请求在断线期间保留，重连后使用当时的新鲜稳定结果
  回复。
- 转盘完整写入7字节、圆环/码垛完整写入11字节、物料完整写入6字节后，
  对应请求或周期才会被标记为已完成。

摄像头异常同样不会结束程序：

- 启动时未接入摄像头，或采集过程中读取失败时，预览窗口显示
  `Waiting for camera connection...`。
- 默认每1秒尝试重新打开 `/dev/video0`，可以通过
  `--camera-reconnect-interval` 修改重连间隔。
- 断线时清除圆心种子、物料运动历史和稳定窗口，不显示或发送旧结果。
- 当前视觉模式、连续上报策略和待完成的单次请求都会保留；重连后必须
  重新获得新鲜稳定结果，才恢复发送或完成应答。

终端每秒输出一次串口状态：

- `Serial=CONNECTED/RETRYING`
- `Report=INACTIVE/WAITING/CONTINUOUS/ON_REQUEST`（三圆环状态带 `RING_`
  前缀，码垛状态带 `STACKED_` 前缀）
- `Pending=True/False`
- `Last=最后一次发送的整数坐标`
- `TurntableSent=累计转盘中心帧数`
- `RingSent=累计圆环结果帧数`（每帧同时包含2号圆心和实际连线角度）
- `MaterialSent=累计物料颜色批次数`
- `Task=当前有效任务码`，未收到时显示 `--`
- `TaskRx=累计收到的合法任务码帧数`
- `TaskInvalid=累计拒绝的非法任务码帧数`

## 9. 键盘调试对应关系

键盘仅用于电脑端调试，不属于串口协议：

| 按键 | 功能 |
|---|---|
| `A` | 进入转盘识别并恢复静默等待状态 |
| `M` | 进入物料抓取模式并启动一次上报周期 |
| `R` | 进入三圆环工位识别并恢复静默等待状态 |
| `S` | 进入中环加上下长边码垛识别并恢复静默等待状态 |
| `D` | 进入两点像素测量；再次按 D 清空并重新开始 |
| `I` | 返回 Idle |
| 测量模式鼠标左键 | 第一次选 P1 并冻结画面；第二次选 P2，显示坐标、DX、DY 和像素距离；第三次清空并恢复实时画面 |
| `Q` / `Esc` | 退出视觉程序 |

Idle 中点击不记录测量点。测量坐标遵循图像处理配置，`DX=X2-X1`、
`DY=Y2-Y1` 保留正负号，直线距离单位为像素；第三次点击不作为下一轮
的起点。冻结期间串口和相机采集继续运行，切换模式或相机断线时清空测量。

主程序采用普通函数组织：`set_mode()` 统一切换模式，
`handle_serial_command()` 解释控制指令，各 `process_*()` 函数负责对应
模式的检测、绘制和上报。修改快捷键查看 `handle_key()`；修改算法阈值
查看 `config/`；修改检测步骤查看对应检测器的 `detect()`。

## 10. 高位物料区域标定

首次使用物料模式，或摄像头抬起后的固定姿态发生变化时，运行：

```bash
python3 code/物料抓取区域标定.py
```

在畸变矫正画面中依次框选：整个物料活动区、左抓取区、右抓取区、下抓取
区，然后按 `S` 保存。`U` 撤销最后一个区域，`R` 清空重来。三个抓取区
必须位于活动区内且不能重叠。

默认配置处于 `calibrated=false` 安全状态。在完成四区域标定前，主程序
可以正常启动，但物料检测只显示 `UNCALIBRATED`，不会发送 `CC 02` 帧。

## 11. 叠放位直线搜索标定

改变摄像头安装高度后，先退出主程序释放摄像头，再运行：

```bash
python3 code/叠放位直线标定.py
```

默认物理尺寸为靶环最外圈直径 **95 mm**，同一平面的上下两条基准线到
中环圆心各 **75 mm**。可使用 `--diameter-mm` 和 `--line-offset-mm`
设置其他尺寸。相机设备、分辨率、相机参数文件及畸变矫正开关与主程序
使用同一套默认值，也可通过 `--device`、`--width`、`--height`、
`--calibration`、`--camera-processing-config` 指定。

请露出完整的最外圈、足够的同心纹理以及上下基准线。三环可见且排列可靠
时自动选中环；不能自动确定时左键点选中环。窗口缩放不改变像素坐标。
绿色椭圆应位于 **95 mm 最外圈**，青色矩形为搜索区域，黄色为候选线，
紫色为通过几何复核的最终基准线。看到 `STABLE` 后仍需核对绿色外圈和
两条实体线是否正确，再按 **S** 确认并保存；**R** 清除重选，**Q/Esc**
退出。目标丢失或相机断线后，旧结果不能保存。保存失败不会替换原配置。
**标定保存仍要求双线连续稳定**；主程序支持单线运行不放宽此要求。
已有搜索标定可直接使用，无需因单线运行而重新标定。

工具只在 `config/stacked_ring_detector.json` 增加 `search_calibration`
标定段，保留其余字段。不自动填入示例标定数据；首次保存后重启主程序
生效。旧配置没有该段时继续运行原检测流程。新流程使用实际外圈尺度
预测搜索区域，并要求检测到真实边缘；它不会把预测线作为检测结果。
局部中环搜索失败时，程序先尝试安装参考位置，再通过全图中的可靠三环
排列重新确定中环，成功后恢复局部跟踪。侧环被物料遮挡时，允许较少的
同心轮廓辅助确认排列，但同时检查侧环残留外圆弧、两侧间距一致性以及
间距与中环尺度的关系；中环仍必须通过原同心轮廓和外圈质量检查，不能
根据两侧位置虚构中环。此兼容仅用于运行时重定位，不降低标定工具要求。
全图失败重试间隔为 0.5 秒，仍保留外圈尺寸和几何检查。若只剩一个环可见且已经偏离局部搜索范围，
不会将任意孤立圆环当成中环，需要露出三环或回到原搜索区域。

该方法使用局部仿射近似，支持轻度椭圆变形，仍保留配置中的小角度直线
约束（默认 ±8°）。外圈轴比小于 0.75、三环间距明显不一致、外圈不完整
或基准线几何关系不符时不接受标定。运行时外圈轴长相对标定变化超过
±20% 时要求重新标定；不支持任意倾角下完全免标定。仅凭未知同心纹理
不能证明所选轮廓必然是95mm外圈，因此保存前的视觉确认不可省略。

标定会记录图像尺寸、矫正开关和参与矫正的相机参数指纹。主程序发现
这些设置不匹配时，码垛界面提示 `Recalibrate stacking` 并停止产生有效
码垛结果，其他识别模式不受影响。没有开启矫正时不读取相机内参文件。

**这是搜索标定，不是纠偏标定。** 工具不改变工位参考圆心、毫米换算矩阵、
底盘纠偏矩阵和串口协议。重新安装后，原有毫米误差是否准确仍需要单独
验证。码垛结果中的两侧圆心仍由原工位参考重建，不代表实际重新识别了
两个侧环。请在新的安装高度上完成实机验证后再使用。


## 12. 桌面启动与开机自启动（当前板子）

桌面上的“视觉程序”快捷方式和用户登录自启动项，都通过
`code/启动视觉.sh` 启动 `code/main.py`。使用 `/usr/bin/python3`，启动时
打开终端显示运行日志和错误信息，不需要在 IDE 中点击运行。

当前板子已经配置 LightDM 自动登录 `orangepi` 的 XFCE 桌面，因此开机
进入桌面后会自动启动视觉程序。它是图形会话自启动，不是在登录前运行。
默认仍进入 Idle，视觉模式由原快捷键或串口命令切换。在摄像头窗口按
**Q / Esc** 退出后，本次登录不会自动再次拉起程序。

启动入口使用进程锁，并检查 IDE 是否已经运行同一路径的 `main.py`；
已运行时提示“视觉程序已经运行”，避免重复占用摄像头和串口。若以后
绕过入口同时手动启动多个 Python 实例，仍需自行避免设备冲突。
程序异常退出时，启动终端保留错误信息，按回车关闭；正常退出直接关闭。

- 登录自启动项：`/home/orangepi/.config/autostart/cyqm-vision.desktop`

“视觉程序”，桌面快捷方式仍然可用。快捷方式和自启动项属于本机用户
设置；复制项目到其他机器时，需要重新安装这两项，并更新其中的路径。
